Glossary

Every term, in plain words

Each word used in the course is explained here once. Terms are added as lessons are published.

No term matches. It may belong to a lesson that is not published yet.

Access mode
A classic compute setting that decides who can use it. Standard (formerly Shared) is for many users. Dedicated (formerly Single user) is for one user or group. First used in 01-04.
Account (Databricks account)
The top level of a company's Databricks setup. It contains the workspaces and is where users, groups and Unity Catalog are managed. First used in 01-01.
ACID
Four guarantees of a reliable table: atomicity, consistency, isolation, durability. Together they mean changes are all-or-nothing and safe. First used in 00-08.
Action
A Spark step that asks for a result or writes data, such as count or write. It makes the whole plan run. First used in 00-05.
Aggregate
To combine many rows into one summary value, such as a total, a count or an average. First used in 00-10.
All-purpose compute
Classic compute for people working by hand in notebooks. It stays on between commands until stopped or idle too long. First used in 01-04.
ANSI mode
A Spark setting that makes invalid conversions and arithmetic fail with an error instead of quietly returning NULL. First used in 03-03.
Apache Spark
Free, open-source software that processes large data by splitting the work across many computers. The engine inside Databricks. First used in 00-05.
Adaptive query execution (AQE)
Spark's run-time optimiser. It checks real data sizes while a query runs and adjusts the plan, for example by merging small shuffle partitions or switching to a broadcast join. First used in 03-12.
ARRAY
A column type holding an ordered list of values of one type. Reach an element by position in square brackets. First used in 02-11.
Auto Loader
The cloudFiles streaming source. It loads new files from a folder exactly once and scales to millions of files. First used in 02-04.
Auto termination
A setting that switches compute off after a chosen period with no activity. First used in 01-04.
Autoscaling
Automatically adding and removing workers between a minimum and a maximum as the load changes. First used in 01-04.
Avro
A row-based binary file format that stores its schema with the data. Common for messages in streaming systems. First used in 00-03.
Baseline
The normal duration of a job, worked out from its recent good runs (for example their median). A new run is compared with it. First used in 06-01.
Batch
Processing a collected pile of data in one go, at intervals. First used in 00-04.
binaryFile
A file format that reads each file as one row with its path, modification time, length and raw content. Used for unstructured files. First used in 02-12.
Branch
A separate line of commits, used to make a change without touching the main line. First used in 05-01.
Branching
Choosing one of several routes through a job, so that only one path runs. First used in 04-06.
Broadcast join
A join in which a small table is copied to every executor, so the large table does not need to be shuffled. First used in 03-05.
Bronze
The layer that holds raw data exactly as it arrived. First used in 00-10.
Bucket
The top-level container for objects in Amazon S3 and Google Cloud Storage. Azure calls it a container. First used in 00-06.
Bundle (Declarative Automation Bundle)
A folder holding code plus a databricks.yml file that describes jobs, pipelines and other resources, so they can be deployed as one unit. Formerly Databricks Asset Bundles. First used in 05-04.
Bundle resource
One Databricks object, such as a job, pipeline or schema, described under resources in a bundle and identified by a resource key. First used in 05-07.
Bundle template
A ready-made starting layout for a new bundle, used by databricks bundle init, such as default-python. First used in 05-09.
Bundle variable
A named placeholder in databricks.yml, used as ${var.name} and filled in when the bundle is deployed. First used in 05-06.
Cast
Converting a value from one data type to another, for example text to a number. First used in 03-03.
Catalog
The first level of a data name in Unity Catalog. It contains schemas. First used in 00-09.
Change data capture (CDC)
Reading a source database's own log of inserts, updates and deletes, and replaying them in the target. First used in 02-01.
CHECK constraint
A table constraint that refuses any write where a stated condition is not true. First used in 03-16.
Checkpoint
Two meanings. (1) In streaming: a saved bookmark of how far an incremental or streaming job has read, so the next run continues from there. (2) In a Delta transaction log: a Parquet file that sums up the table's state at one version, so readers need not replay every commit. First used in 00-04.
CI/CD
Continuous integration and continuous delivery: checking every proposed change automatically, then sending passing changes to the next environment without manual copying. First used in 05-10.
Classic compute plane
Compute that runs on machines in your own cloud account and network. First used in 01-01.
Clone
Copying a remote repository to a local or workspace folder. First used in 05-02.
Cluster
A group of computers working together as one: a driver plus executors. Also the older name for a classic compute resource on Databricks. First used in 00-05.
Clustering key
A column that liquid clustering uses to arrange rows. A table can have up to four. First used in 06-08.
coalesce
A function that returns the first of its arguments that is not NULL. First used in 03-02.
collect()
A Spark action that copies every row of a DataFrame into the driver's memory. Risky on large data. First used in 06-12.
Column
One named fact that every row in a table has, such as price. All values in a column share a data type. First used in 00-02.
Columnar
A way of storing data column by column, so a query can read only the columns it needs. First used in 00-03.
Commit (Delta)
One numbered entry in a Delta table's transaction log, recording the actions of a single change. Each commit creates a new table version. First used in 01-02.
Compression
Making data take up less space by storing repeated patterns more briefly. First used in 00-03.
Compute
The computers that run your code. On Databricks you switch compute on when needed and pay while it is on. First used in 00-06.
Compute plane
Where your data is actually processed, on Spark drivers and executors. Older material calls it the data plane. First used in 01-01.
Compute policy
Rules set by an admin that limit which compute settings users can choose. First used in 06-10.
Compute-scoped library
A library installed on a cluster, available to every notebook and job that uses it. First used in 06-11.
Condition
A test that is true, false or unknown for each row, used in a filter or a join. First used in 03-08.
Configuration profile
A named set of connection details (workspace host and sign-in method) saved by the Databricks CLI in ~/.databrickscfg. First used in 05-08.
Connection
A Unity Catalog object that stores the address and login details for one outside system. Using it needs the USE CONNECTION privilege. First used in 02-03.
Connector
Software that knows how to read from one kind of source. First used in 02-03.
Control plane
The services Databricks runs in its own account to manage everything: the web application, notebooks, job scheduling and starting compute. It does not process your data. First used in 01-01.
COPY INTO
A SQL command that loads files from a folder into a table and skips files it has already loaded. First used in 02-04.
Cross join
A join with no key that pairs every row of one table with every row of the other. First used in 03-05.
CSV
Comma-separated values. A plain-text format with one record per line and commas between values. It stores no data types. First used in 00-03.
DAG (directed acyclic graph)
A set of tasks joined by one-way dependencies, with no loops. The shape of a job's task graph. First used in 04-03.
Dashboard task
A job task that refreshes a dashboard. First used in 04-02.
Data-driven trigger
A trigger that starts a run when data arrives or changes, such as a file arrival or table update trigger. First used in 04-11.
Data engineer
The person who builds and looks after data pipelines, so that correct data arrives on time for everyone else. First used in 00-01.
Data engineering
The work of collecting data, storing it, cleaning it and delivering it in a usable shape. First used in 00-01.
Data skew
Uneven data: one key or partition holds far more rows than the others, so one task runs much longer. First used in 06-06.
Data type
The kind of value a column may hold, such as a whole number (INT), text (STRING), a decimal number (DECIMAL) or a date. First used in 00-02.
Databricks
A cloud platform that runs Apache Spark for you and adds storage management, security and tools around it. First used in 00-07.
Databricks CLI
The command-line tool for Databricks. Its bundle commands validate, deploy and run bundles. First used in 05-04.
Databricks Runtime
The bundle of software installed on classic compute: a version of Apache Spark plus libraries. LTS versions are supported for longer. First used in 01-04.
DataFrame
A table of rows and columns that you work with in Spark code. The data is held by the cluster, not by your own computer. First used in 00-05.
DBU (Databricks Unit)
A standard unit of processing power used for one hour. Databricks charges by DBUs used multiplied by a price per DBU. First used in 01-05.
Deduplication
Removing repeated rows so that each thing is kept once. Whether rows are copies depends on the columns you compare. First used in 03-10.
Delta Lake
An open-source table format: Parquet data files plus a transaction log. The default format for tables on Databricks. First used in 00-08.
Deployment mode
A target setting, development or production. Development prefixes names and pauses schedules; production does not and adds checks. First used in 05-05.
Detached HEAD
A state where Git is not on any branch. Changes made there can be lost unless a branch is created first. First used in 05-02.
Dimension table
A table that describes the things a fact refers to, such as shops, products or dates. First used in 03-15.
Directory listing
Auto Loader's default way of finding new files: asking cloud storage for the folder's contents and comparing with its checkpoint. First used in 02-06.
Driver
The one computer in a Spark cluster that plans the work and hands tasks to the executors. First used in 00-05.
Duration threshold
A job setting for run duration: a warning time that raises a duration warning event, and a timeout that stops the run as Timed Out. First used in 06-01.
ELT
Extract, Load, Transform. Raw data is stored first and cleaned afterwards, so a raw copy always exists. First used in 00-01.
Environment
A separate place where a project runs, such as dev, test or prod, often its own workspace or catalog. First used in 05-05.
ETL
Extract, Transform, Load. Data is cleaned on the way in, before it reaches your storage. First used in 00-01.
Event log (compute)
The list of everything that happened to a compute resource: starts, resizes, init scripts and terminations. Found on the compute details page. First used in 06-10.
Exchange
The step in a Spark query plan where data is shuffled between partitions. First used in 06-05.
Executor
A worker in a Spark cluster. Executors do the actual reading and processing of data. First used in 00-05.
Expectation
A data quality rule attached to a pipeline dataset. Its action for a bad row is to warn, drop it, or fail the update. First used in 03-16.
explode
A function that turns an array into rows, one row per element. First used in 02-11.
External location
A Unity Catalog object that pairs a cloud storage path with a storage credential, making that path usable under governance. First used in 01-03.
External table
A table that points at files in a storage path you chose. Dropping the table leaves the files in place. First used in 01-03.
External volume
A volume that points at an existing folder in cloud storage. Dropping it leaves the files in place. First used in 02-02.
Fact table
A table of events, one row each, holding numbers to add up and keys to descriptive tables. First used in 03-15.
Failure rate
Failed runs divided by finished runs over a time window, such as the last 30 days. First used in 06-03.
File
A named lump of data in storage. Nothing checks what is inside it. First used in 00-02.
File arrival trigger
A job trigger that starts a run when new files appear in a watched external location or volume path. Settings include wait after last change and minimum time between triggers. First used in 04-09.
File events
The recommended form of file notification, enabled once on a Unity Catalog external location and shared by all streams reading from it. First used in 02-06.
File format
The rules for how data is laid out inside a file, such as CSV, JSON or Parquet. First used in 00-03.
File notification
A way for Auto Loader to find new files from messages sent by cloud storage, without listing the folder. First used in 02-06.
Filter
A transformation that keeps only the rows for which a condition is true. First used in 03-08.
For each task
A job task that runs one nested task once for each item in a list. Each run is an iteration. First used in 04-07.
Git
A version control system that records every change to a set of files, with who made it and why. First used in 05-01.
Git folder
A repository cloned into a Databricks workspace folder. Formerly called a Databricks Repo. First used in 05-02.
Gold
The layer that holds data shaped for one particular use, usually summaries for reports and dashboards. First used in 00-10.
Governance
The rules and tools that control who can see or change which data, and that keep a record of it. First used in 00-01.
Grain
What one row of a table represents, such as one sale line or one shop per day. First used in 03-15.
Group by
Sorting rows into groups that share a value, so that aggregates can be worked out for each group. First used in 03-11.
High-water mark
The largest value of an ever-growing column, such as an ID or a last-updated time, that you have already loaded. The next load asks only for rows above it. First used in 02-01.
Idempotent
Giving the same end result however many times it is run. An idempotent load can be retried safely. First used in 02-04.
If/else condition task
A job task that compares two operands and sends the run down a true or false path. First used in 04-06.
Incremental
Processing only the data that is new since the last run, instead of everything again. First used in 00-04.
Information schema
A ready-made schema called information_schema inside every catalog. Its tables describe that catalog's own tables, columns and privileges. First used in 01-03.
Ingestion
Bringing data in from a source and making a copy of it, without changing it. First used in 00-01.
Ingestion gateway
The part of a managed database connector that continuously extracts changes from the source. It runs on classic compute. First used in 02-08.
Ingestion pipeline
The part of a managed connector that loads data into destination streaming tables. It runs on serverless compute on a schedule. First used in 02-08.
Init script
A shell script that runs on each node of classic compute before Spark starts, for example to install system packages. First used in 06-10.
Inner join
A join that keeps only rows that have a match in both tables. First used in 03-04.
JDBC
A long-established standard that lets programs built on Java technology, including Spark, connect to databases through a driver. First used in 02-09.
Job
The definition of an automated workflow: its tasks, their order, its schedule and settings. First used in 04-01.
Job parameter
A value supplied when a job runs, referenced in the job definition as {{job.parameters.name}}. First used in 04-05.
Jobs compute
Classic compute created for one job run and removed when the run ends. It has a lower price per DBU than all-purpose compute. First used in 01-04.
Join
Combining two tables by matching rows on a key, and putting their columns side by side. First used in 03-04.
Join key
The column or columns whose values must match for two rows to be joined. First used in 03-04.
JSON
A plain-text format in which every value carries its label. It can hold nested data, so it suits semi-structured data. First used in 00-03.
Lakeflow Connect
The Databricks family of ingestion tools. It has managed connectors and standard connectors. First used in 02-01.
Lakeflow Jobs
The Databricks orchestrator for running tasks in order, on a schedule, with a record of each run. Formerly Databricks Workflows. First used in 04-01.
Lakehouse Federation
A Databricks feature for querying an outside database in place, as if its tables were in Unity Catalog, without copying the data. First used in 02-09.
Latency
The delay between something happening and it showing up in your tables. First used in 00-04.
Lazy evaluation
Spark's habit of only recording steps in a plan, and doing no work until a result is asked for. First used in 00-05.
Leaf task
A task with no tasks after it in the task graph. The overall result of a run is based on its leaf tasks. First used in 06-02.
Left join
A join that keeps every row from the left table, with NULLs where there is no match on the right. First used in 03-04.
Lineage
An automatic record of which tables and columns were used to build which others. First used in 01-03.
Liquid clustering
A Delta table layout that keeps rows with similar values of chosen keys in the same files, so queries can skip files. Keys can change without rewriting data. First used in 06-08.
Managed connector
A ready-made, fully managed ingestion pipeline for a specific application or database. You configure what to ingest and cannot change how. First used in 02-03.
Managed storage location
The storage path where Unity Catalog puts the files of managed tables and volumes. It can be set on a schema, a catalog or the metastore, and the most specific one wins. First used in 01-03.
Managed table
A table whose files Unity Catalog places and looks after. Dropping the table removes the files too. The default kind. First used in 01-03.
Managed volume
A volume whose files Unity Catalog places and looks after. Dropping it removes the files. First used in 02-02.
Materialized view
A table-like object that stores the results of a query and is refreshed to match its source. First used in 03-14.
Matrix view
The grid on a job's Runs tab. Each column is a run and each row a task; bar height shows duration and colour shows the result. First used in 06-01.
Medallion architecture
A pattern of organising tables in three layers of rising quality: bronze, silver and gold. First used in 00-10.
MERGE
A SQL statement that updates rows which already exist and inserts rows which do not, in one commit. Often called an upsert. First used in 01-02.
Merge conflict
A stop in a merge that happens when the same lines changed differently on both branches. Someone must choose which version to keep. First used in 05-03.
Metastore
The top-level container in Unity Catalog, normally one per cloud region. Workspaces are attached to it. First used in 00-09.
Metric view
A Unity Catalog object that defines business measures once, for consistent use in reports and dashboards. First used in 03-14.
Micro-batch
A very small batch. By default Spark streams by running many micro-batches one after another. First used in 00-04.
Narrow transformation
A step that works on each partition where it already is, with no data moving between machines, such as filter or select. First used in 06-05.
Nested data
Data inside other data, such as a customer record inside an order record. First used in 02-11.
Nested task
The task inside a For each task, run once per iteration with the current item available as {{input}}. First used in 04-07.
NOT NULL
A table constraint that refuses any write where the column has no value. First used in 03-16.
Notebook
A document made of cells of code and notes. You run a cell and see its result directly underneath. First used in 00-07.
Notebook-scoped library
A library installed with %pip inside one notebook, visible only to that notebook session. First used in 06-11.
Notebook task
A job task that runs a notebook. First used in 04-02.
NULL
A marker meaning "no value" or "unknown". It is not zero and not empty text. First used in 00-02.
Object
One stored file in object storage, together with its key. First used in 00-06.
Key (object key)
The full name of an object in a bucket, such as orders/2026/11/16/north.csv. First used in 00-06.
Object storage
A cloud service that stores files cheaply and without a practical size limit. Amazon S3, Azure Data Lake Storage and Google Cloud Storage are examples. First used in 00-06.
ODBC
A language-neutral standard for connecting programs to databases through a driver. Widely used by reporting tools. First used in 02-09.
Out-of-memory error (OOM)
A failure that happens when a process needs more memory than it has. On Spark, the driver or an executor can run out. First used in 03-13.
Optimistic concurrency control
Delta's way of handling simultaneous writers: nobody locks the table, everyone writes, and conflicts are checked only at the moment of committing. First used in 01-02.
OPTIMIZE
A command that rewrites many small data files of a Delta table into fewer large ones, so reads are faster. First used in 01-02.
ORC
A columnar binary file format similar to Parquet, mostly met in older Hadoop systems. First used in 00-03.
Orchestration
Running the steps of a pipeline in the right order, at the right time, and retrying them when they fail. First used in 00-01.
Override
A value that replaces a default for one case, such as a target setting its own value for a variable. First used in 05-06.
Pagination
Receiving a large result in pages and requesting each page in turn. First used in 02-10.
Parquet
A columnar, compressed file format that stores its own schema. Delta tables keep their data in Parquet files. First used in 00-03.
Partition
One chunk of a dataset that Spark works on as a unit. One executor handles one partition at a time. First used in 00-05.
Partner Connect
A workspace page that sets up connections to other companies' data tools, including ingestion products. First used in 02-13.
Photon
A faster engine for running SQL and DataFrame code on Databricks. First used in 01-04.
Pipeline (data pipeline)
A chain of steps that moves data from its source to the people who use it, and runs repeatedly without manual work. On Databricks the word can also mean the product Lakeflow Spark Declarative Pipelines. First used in 00-01.
Pipeline task
A job task that runs a Lakeflow Spark Declarative Pipeline. First used in 04-02.
Pool
A set of idle, ready machines kept waiting so that classic compute drawing from it starts faster. First used in 01-04.
Predictive optimization
A Databricks feature that runs OPTIMIZE, VACUUM and ANALYZE automatically on Unity Catalog managed tables when it expects a benefit. First used in 06-09.
Prefix
The beginning of an object key, used like a folder path to select a group of objects. First used in 00-06.
Primary key
A column or set of columns that is meant to identify each row. On Unity Catalog tables it is informational and not enforced. First used in 03-16.
Privilege
A permission to do one kind of thing to one object, such as SELECT on a table. Given with GRANT, removed with REVOKE. First used in 00-09.
Promotion
Moving the same code from one environment to the next, for example from dev to test to prod. First used in 05-05.
Pull request
A request to review a branch and merge it into another, usually main. Created on the Git host. First used in 05-01.
Push
Sending local commits to the remote branch. First used in 05-03.
PySpark
The Python way of using Apache Spark. First used in 00-01.
Quartz cron expression
A six-field timetable notation (seconds, minutes, hours, day-of-month, month, day-of-week) used for job schedules. Day-of-month and day-of-week cannot both be set; one uses ?. First used in 04-08.
Query profile
A Databricks view of how a SQL query or serverless command ran, step by step, with time and rows per step. Used where the Spark UI is not available. First used in 06-04.
Rate limit
A cap on how many requests an API accepts in a period. Exceeding it brings a "slow down" response. First used in 02-10.
read_files
A SQL function that reads files from a path and returns them as rows, so files can be queried or loaded into a table. First used in 02-02.
Remote
A copy of a repository on a shared server, such as GitHub or Azure DevOps. First used in 05-01.
Repair run
Re-running only the failed, canceled and skipped tasks of a job run, plus the tasks after them, while keeping the tasks that succeeded. First used in 06-02.
Repository (repo)
A project and its complete history of commits. First used in 05-01.
Rescued data column
A spare column, _rescued_data, where Auto Loader keeps data that did not fit the schema: new columns, wrong types, wrong letter case. First used in 02-07.
Resource reference
A placeholder such as ${resources.pipelines.sales.id} that points at another resource in the same bundle and becomes its real value at deploy. First used in 05-07.
REST API
A common way for programs to request data from a web address. The answer usually comes back as JSON. First used in 02-10.
Retry
An automatic second or later attempt at a failed task, within a limit set by max_retries. First used in 04-04.
Row
One record in a table: one order, one customer, one event. First used in 00-02.
Run
One execution of a job, with a record of the status and timing of each task. First used in 04-01.
Run if
The rule that decides whether a task runs, based on how its upstream tasks finished. The default is All succeeded. First used in 04-03.
Salting
Adding a random number to a hot key so its rows spread across several partitions, then combining the results. First used in 06-06.
Slowly changing dimension (SCD)
A way of storing changes to a row. Type 1 overwrites and keeps only the latest values. Type 2 keeps every version, with start and end markers. First used in 02-08.
Scheduled trigger
A job trigger that starts runs at times set by a Quartz cron expression and a timezone. First used in 04-08.
Schema
Two meanings. (1) The list of column names and data types of one table. (2) In Unity Catalog, a container inside a catalog that holds tables, views and volumes. Also called a database. First used in 00-02.
Schema enforcement
The default behaviour of a Delta table: a write whose columns or types do not match the table is refused. First used in 01-02.
Schema evolution
Deliberately letting a table's schema change during a write, for example adding a new column with the mergeSchema option. First used in 01-02.
Schema hints
Types you state for particular columns while leaving the rest of the schema to be inferred. Set with cloudFiles.schemaHints. First used in 02-07.
Schema inference
Working out column names and types by sampling the data, instead of being told them. First used in 02-07.
Schema location
The folder where Auto Loader stores the schema it has inferred, set with cloudFiles.schemaLocation. First used in 02-05.
Secret
A password, key or token kept in a protected store and read at run time with dbutils.secrets.get, so it never appears in code. First used in 02-09.
Securable object
Anything in Unity Catalog that permissions can be granted on, such as a catalog, schema, table, volume or external location. First used in 01-03.
Semi-structured data
Data with labels but a loose shape, where records can differ and can contain lists or sub-records. JSON is the usual example. First used in 00-02.
Serverless
Compute that Databricks sets up, sizes and runs for you. You choose it and it is ready in seconds. First used in 00-07.
Serverless compute plane
Compute that runs on machines in the Databricks account, in the same region as your workspace. First used in 01-01.
Service principal
A non-human identity used by automated tools and jobs, so they do not run as a person. First used in 05-08.
Shuffle
Redistributing rows between partitions and machines so that rows with the same key meet. Used by joins, grouping and sorting, and the slowest step in many jobs. First used in 03-05.
Silver
The layer that holds cleaned, checked, deduplicated data with proper types. First used in 00-10.
SKU
A price label for one kind of usage. Each compute type has its own SKU and its own price per DBU. First used in 01-05.
Snapshot (full load)
A complete copy of a source taken at one moment. A snapshot load replaces everything in the target each time. First used in 02-01.
Source
Any place data comes from: an app's database, a file, a website, a sensor. First used in 00-01.
Spark job
The work Spark starts for one action, such as writing a table. Not the same as a Lakeflow job. First used in 06-04.
Spark task
The smallest unit of Spark work: one stage applied to one partition. Not the same as a task in Lakeflow Jobs. First used in 06-04.
Spark UI
Web pages that show what Spark did: its jobs, stages and tasks, with timings and memory use. Opened from the compute details page. First used in 06-04.
Spill
Data a task writes to local disk because it ran out of working memory, then reads back. It slows a stage but does not fail it. First used in 06-07.
SQL
Structured Query Language. The standard language for asking questions of tables and changing them. First used in 00-01.
SQL task
A job task that runs a SQL query or saved SQL file on a SQL warehouse. First used in 04-02.
SQL warehouse
Compute built for running SQL, used by the SQL editor, dashboards and reporting tools. First used in 00-07.
Stage
A part of a Spark job that runs without moving data between machines. Shuffles split a Spark job into stages. First used in 06-04.
Standard connector
An ingestion building block, such as Auto Loader, that you configure and run inside your own pipeline or job. First used in 02-03.
Star schema
A layout with one fact table in the middle and dimension tables around it. First used in 03-15.
Storage credential
A Unity Catalog object holding the cloud login that lets Databricks reach a storage bucket. First used in 01-03.
Streaming
Processing data continuously, shortly after each piece arrives. First used in 00-04.
Streaming table
A table that processes only new data each time it refreshes. In SQL it is the usual way to use Auto Loader. First used in 02-03.
STRUCT
A column type holding a record with a fixed set of named fields. Reach a field with a dot. First used in 02-11.
Structured data
Data that already fits neatly into rows and columns. First used in 00-02.
Structured Streaming
The part of Apache Spark that processes data which keeps arriving, using the same DataFrame code as batch. First used in 00-04.
System tables
Tables in the built-in system catalog that record how the platform is used: audit events, lineage, billing and more. First used in 01-03.
Table
Data arranged in rows and columns, with a schema that every row must fit. First used in 00-02.
Table update trigger
A job trigger that starts a run when named Unity Catalog tables change. Settings include any or all condition, wait after last change and minimum time between triggers. First used in 04-10.
Target
A named entry under targets in databricks.yml that says where a bundle deploys and which settings change there. First used in 05-05.
Task
One step inside a job, such as one notebook, one query or one pipeline. First used in 04-01.
Dependency (task)
A link that makes one task wait for another, set with depends_on. First used in 04-03.
Task value
A small result set by one task and read by later tasks in the same run, referenced as {{tasks.task_key.values.name}}. First used in 04-05.
Temporary view
A name given to a DataFrame so that SQL in the same session can use it. It is not stored in the catalog and disappears with the session. First used in 03-01.
Terminal
A window where you type text commands and read the replies. First used in 05-08.
Termination reason
The reason code recorded when compute stops, such as INIT_SCRIPT_FAILURE or DRIVER_OUT_OF_MEMORY. First used in 06-10.
Three-level namespace
The naming scheme catalog.schema.object used for everything in Unity Catalog. First used in 00-09.
Time-based trigger
A trigger that starts runs at set times, whether or not new data has arrived. A scheduled trigger is time-based. First used in 04-11.
Time travel
Reading a Delta table as it was at an earlier version or time. First used in 00-08.
Transaction log
The ordered record of every change to a Delta table, kept in its _delta_log folder. It decides which data files are part of the table. First used in 00-08.
Transformation (pipeline stage)
Changing data to make it useful: fixing errors, removing duplicates, combining tables, adding things up. First used in 00-01.
Transformation (Spark)
A single lazy step in Spark, such as filter or select. It describes a new DataFrame and runs nothing by itself. First used in 00-05.
Trigger
The setting that says when a job or stream should run or look for new data. For a stream, examples are availableNow and processingTime. First used in 00-04.
Union
Stacking the rows of two tables that have the same kind of columns. UNION ALL keeps duplicates; UNION removes them. First used in 03-06.
Unity Catalog
The part of Databricks that keeps one index of all data and checks every access against the permissions that were granted. First used in 00-09.
Unstructured data
Data with no rows or columns at all, such as images, audio and PDF documents. First used in 00-02.
Upstream failed
A task status meaning the task did not run because a task it depends on failed. First used in 06-02.
VACUUM
The command that permanently deletes data files a Delta table no longer uses, once they are older than the retention period. First used in 00-08.
VARIANT
A column type that stores a whole semi-structured value of any shape, with no schema needed up front. First used in 02-11.
View
A saved query that you can read like a table. It holds no data of its own. First used in 00-09.
Volume
A Unity Catalog object that holds files which are not tables, reached by a path starting /Volumes/. First used in 00-09.
Wide transformation
A step that needs rows with the same key together, so it causes a shuffle, such as join, groupBy or distinct. First used in 06-05.
Window function
A function that works out a value for each row by looking at a group of related rows, without collapsing them. row_number() is the common one. First used in 03-10.
Workflow file
A text file kept in a repository that tells a CI service what to run and when, such as on every pull request. First used in 05-10.
Workload
A piece of work that needs compute, such as a dashboard, a scheduled job or a session of exploring data. First used in 01-06.
Workload identity federation
A way for an automated job to prove who it is with a short-lived token from its CI service, so no long-lived password or token is stored. First used in 05-10.
Workspace
The Databricks website you log in to. It holds notebooks, jobs and settings, organised in folders. First used in 00-07.
Workspace storage
A storage bucket in your cloud account that holds a classic workspace's own housekeeping files, such as job results and logs. It is separate from your table data. First used in 01-01.
YAML
A plain-text format for settings that uses indentation and name: value pairs. Bundle configuration is written in YAML. First used in 05-04.
Z-order
An older way to place related data in the same Delta files, using OPTIMIZE ... ZORDER BY. Liquid clustering replaces it for new tables. First used in 06-08.
