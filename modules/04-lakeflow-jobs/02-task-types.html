Task types in Lakeflow Jobs

A task does one kind of work. The kind decides what the task runs, which compute it uses and how you configure it. The main types match the things you have already built in this course.

04-01 Jobs, tasks and runs
The idea

Pick the task type by what the work is

Every task has a type. The type says what runs inside it:

  • Notebook task: runs a notebook you wrote, in Python, SQL, Scala or R. Use it for code you need to run with logic and steps.
  • SQL task: runs a SQL query, or a saved file of SQL, on a SQL warehouse. Use it for SQL work that feeds reports.
  • Dashboard task: refreshes a dashboard, so its figures are current when people open it.
  • Pipeline task: runs a Lakeflow Spark Declarative Pipeline (formerly Delta Live Tables), so the transformation is part of the job.

Other types exist for Python scripts, wheels, JAR files and control flow such as If/else and For each. Check the task-type list in the docs for the version you use: the set grows over time.

Everyday analogy

A toolkit, with one tool per job. A cook uses a knife for chopping, an oven for baking and a thermometer for checking. Each tool has its own instructions. The same meal needs all three, in order. A notebook task is the knife: flexible, for any work with code. A SQL task is a measuring jug: exact, for one kind of quantity. A pipeline task is a ready-made oven program: it knows its own steps.

How it works

Type decides what runs, and where

Four common types. Each does one kind of work and needs a compatible compute.

Choosing a type

Code with logic

A notebook task. It can loop, branch, call functions and read files.

SQL for reporting

A SQL task on a SQL warehouse. Simple to read and review.

Keep a report fresh

A dashboard task, run after the tables it reads are updated.

A transformation pipeline

A pipeline task, so the pipeline's own rules and retries apply.

Code

Two task types, written as a job

name: weekly_sales_report
tasks:
  - task_key: build_weekly_totals
    # A SQL task: a query run on a SQL warehouse.
    sql_task:
      warehouse_id: "abc123def456"        # the SQL warehouse to use
      query:
        query_id: "a1b2c3"               # a saved query in the workspace

  - task_key: refresh_dashboard
    # A dashboard task: refreshes the dashboard after the query above.
    depends_on:
      - task_key: build_weekly_totals
    dashboard_task:
      dashboard_id: "sales-overview"

  - task_key: profile_silver
    # A notebook task: Python code with logic of its own.
    notebook_task:
      notebook_path: /Workspace/bakery/profile_silver

Field names are illustrative and vary by version: check the task reference for exact keys and IDs before using them. The pattern to remember is one type per task, and the type decides the keys.

What if I change this?

Changing a task's type or settings

ChangeEffect
Move a SQL task's query into a notebook taskThe same work now runs as code. You gain logic and loops, and lose the simple SQL review and warehouse sizing.
Point a SQL task at a smaller SQL warehouseCheaper, but queries may queue or run slower.
Run a dashboard refresh before the tables it reads are rebuiltThe dashboard shows old figures. Add a dependency so it waits.
Use a notebook task to run a pipeline's code directlyThe pipeline's rules, quality checks and retry behaviour are bypassed. Use a pipeline task.
Change a notebook task's compute from classic to serverlessStartup is faster and the settings you can choose are fewer. Check the language and library limits first.

ScenarioWhat happensFix

Don't confuse these

Task type traps

SQL task vs SQL in a notebook

A SQL task runs on a SQL warehouse and is configured as a task. SQL cells in a notebook run on the notebook's compute.

Dashboard task vs dashboard

A dashboard is what readers look at. A dashboard task refreshes it as part of a job.

Pipeline task vs notebook

A pipeline task runs a declarative pipeline with its own quality rules. A notebook does not get those rules.

Check yourself

Quiz

1. Which task type is right for a SQL query that feeds a weekly report?

A SQL task runs queries on a SQL warehouse, the usual home for reporting SQL.

2. Which task type refreshes a dashboard as part of a job?

The dashboard task refreshes the dashboard as one step.

3. Why run a declarative pipeline as a pipeline task rather than from a notebook?

A pipeline task keeps the pipeline's behaviour intact. Running its code from a notebook can bypass it.

4. In the demo, a SQL aggregation was typed into a notebook task. What did the checker say?

The work is a SQL query, so a SQL task suits it best.

Wrap up

Key takeaways

  • Each task has one type that decides what runs.
  • Notebook for code with logic. SQL for queries on a SQL warehouse. Dashboard to refresh a report. Pipeline for a declarative pipeline.
  • The type also decides the compute the task needs.
  • Use the type that keeps the work's own rules and checks in force.
