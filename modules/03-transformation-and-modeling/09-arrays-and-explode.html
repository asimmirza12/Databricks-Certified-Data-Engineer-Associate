Arrays and explode

Sometimes one cell holds a whole list: the items in a basket, the tags on a product. To count or filter the things in that list, you first have to give each one a row of its own.

The idea

One row per list becomes one row per item

An array is a column type that holds an ordered list of values in a single cell. An order row might have an items column containing ["Loaf", "Bun", "Bagel"].

Arrays arrive in two ways. Nested JSON brings them ready-made (lesson 02-11). Or you create one yourself, by using split on text such as "Loaf,Bun,Bagel".

A list in a cell is compact, but most questions cannot be asked of it directly. "How many Buns were sold?" needs each Bun to be countable. The function explode does that. It takes each row and produces one output row for every element in its array. The other columns are copied onto each new row.

An order with three items goes in as one row and comes out as three. The table gets longer, and each row is now about one item instead of one order.

Everyday analogy

Unpacking a shopping bag onto the checkout belt. A bag is one thing, but the cashier cannot scan a bag. Each item has to be lifted out and placed on the belt separately. Afterwards there are many items where there was one bag, and each still belongs to the same customer. Explode is the unpacking. And an empty bag puts nothing on the belt at all, which matters, as you will see.

How it works

Explode copies the row once per element

The reverse journey also exists. After exploding and working on the items, you can gather them back into one list per order with collect_list, which is an aggregate function used with groupBy.

Working with arrays

from pyspark.sql import functions as F

orders = spark.table("bakery.silver.orders")    # order_id, items_text such as "Loaf,Bun"

# Make an array from text.
with_array = orders.withColumn("items", F.split("items_text", ","))

# Ask things of the array without exploding it.
checked = (with_array
    .withColumn("item_count", F.size("items"))                       # how many elements
    .withColumn("has_bun", F.array_contains("items", "Bun"))        # true or false
    .withColumn("first_item", F.col("items").getItem(0)))

# One row per item. Orders with an empty or NULL array are dropped.
lines = with_array.select("order_id", F.explode("items").alias("item"))

# Keep those orders too, with NULL as the item.
lines_all = with_array.select("order_id", F.explode_outer("items").alias("item"))

# Also return each item's position in the list (0, 1, 2 ...).
numbered = with_array.select("order_id", F.posexplode("items").alias("position", "item"))

# Now ordinary questions work.
display(lines.groupBy("item").count())

# And back again: one row per order, items gathered into a list.
regrouped = lines.groupBy("order_id").agg(F.collect_list("item").alias("items"))
-- In SQL, explode is used in the FROM clause.
SELECT o.order_id, item
FROM bakery.silver.orders AS o,
     LATERAL explode(split(o.items_text, ',')) AS t(item);

-- The older spelling, still widely seen:
SELECT order_id, item
FROM bakery.silver.orders
LATERAL VIEW explode(split(items_text, ',')) exploded AS item;

-- Array questions without exploding.
SELECT order_id, size(split(items_text, ',')) AS item_count
FROM bakery.silver.orders
WHERE array_contains(split(items_text, ','), 'Bun');
What if I change this?

Explode and its relatives

ChangeEffect
explodeOne row per element. Rows whose array is empty or NULL produce nothing and disappear.
explode_outerThe same, except those rows are kept, with NULL in the new column.
posexplodeLike explode, with an extra column giving each element's position, starting at 0.
Sum an order-level column after explodingIt is counted once per item. An order total of 10 with three items sums to 30. Add up item-level values instead.
Explode two array columns in the same stepNot allowed in one select. Done one after the other, you get every combination, which is rarely what you want.
split text that has spaces after the commasThe pieces keep their leading spaces: " Bun" is not "Bun". Trim them, or split on a pattern that includes the space.
collect_list instead of collect_setcollect_list keeps duplicates. collect_set keeps each distinct value once. Neither promises an order.
size of a NULL arrayNot 0. Depending on settings it is NULL or -1. Do not use it to mean "no items" without checking.

Don't confuse these

Array traps

explode vs explode_outer

The only difference is rows with an empty or NULL array: dropped, or kept with NULL.

split vs explode

split turns text into an array and keeps one row. explode turns an array into many rows. They are often used together, in that order.

explode vs collect_list

Opposites. One spreads a list over rows. The other gathers rows into a list.

More rows is expected

Unlike a join, an increase in rows after explode is the whole point. The danger is summing columns that were copied.

Check yourself

Quiz

1. A table has three orders with 2, 3 and 0 items in their arrays. How many rows does explode return?

2 + 3 = 5. The order with an empty array produces no rows.

2. The same table with explode_outer. How many rows?

The empty order is kept as one row with a NULL item: 2 + 3 + 1.

3. Which function turns the text "Loaf,Bun" into an array?

split cuts text into an array. explode then turns that array into rows.

4. In the demo, what did posexplode add compared with explode?

It returns the position, starting at 0, alongside each element.

5. An order has order_total = 10 and three items. After explode, what is SUM(order_total) for that order?

The total is copied onto each of the three item rows, so summing it counts it three times.

Wrap up

Key takeaways

  • An array holds a list in one cell. split makes one from text.
  • explode gives one row per element and copies the other columns.
  • explode drops rows with empty or NULL arrays. explode_outer keeps them.
  • After exploding, do not sum columns that were copied from the original row.
  • size and array_contains answer simple questions without exploding.
