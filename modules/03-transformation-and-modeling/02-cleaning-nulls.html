Cleaning nulls

Raw data is full of holes. A missing price, an empty shop name, the text "n/a" where a number should be. Before anything else can be trusted, you must decide what to do with each hole.

The idea

Three things you can do with a missing value

NULL is the marker for "no value here". It does not mean zero and it does not mean empty text. It means "unknown".

When a column has NULLs you have three honest choices.

  • Drop the row. If an order has no order ID, the row is useless. Remove it.
  • Fill in a value. If a delivery note is missing, an empty note is a fair replacement. Put a stand-in value there.
  • Leave it. If a price is unknown, it is unknown. Inventing a number would be a lie. Keep the NULL and let later steps handle it knowingly.

The skill is choosing per column. There is no single rule for a whole table.

One more job comes first. Sources often disguise a missing value as real text: "n/a", "-", "unknown", or just spaces. Spark does not know these mean "missing". You have to turn them into proper NULLs before any of the three choices can work.

Everyday analogy

A class register with blanks. A pupil with no name on the sheet cannot be marked at all: strike the line. A blank in "packed lunch or school dinner" can safely default to "school dinner". But a blank in "exam score" must stay blank. Writing 0 would drag the class average down for a pupil who was simply absent.

How it works

NULL does not behave like a value

NULL follows its own rules, and they surprise people.

  • Any comparison with NULL gives NULL, not true or false. price = NULL is never true, even when price is NULL. To test for it, use IS NULL and IS NOT NULL, or in PySpark .isNull() and .isNotNull().
  • Filters keep only rows where the condition is true. So WHERE price > 3 silently leaves out rows with a NULL price. So does WHERE NOT (price > 3).
  • Sums and averages skip NULLs. The average of 4, 2 and NULL is 3, not 2.
  • Arithmetic with NULL gives NULL. price * qty is NULL if either one is NULL.

Code

Finding and treating NULLs

from pyspark.sql import functions as F

orders = spark.table("bakery.bronze.orders_raw")

# 1. Measure first: how many NULLs in each column?
display(orders.select([
    F.sum(F.col(c).isNull().cast("int")).alias(c) for c in orders.columns
]))

# 2. Turn disguised missing values into real NULLs.
orders = orders.replace(["n/a", "-", ""], None, subset=["price", "shop"])

# 3. Drop rows that cannot be used without their key.
orders = orders.dropna(subset=["order_id"])

# 4. Fill where a default is truthful. A dictionary gives each column its own value.
orders = orders.fillna({"shop": "Unknown", "note": ""})

# 5. Take the first non-NULL of several columns.
orders = orders.withColumn("contact", F.coalesce("email", "phone", F.lit("none given")))

# price is left alone: an unknown price stays NULL.
-- The same ideas in SQL.
SELECT
  order_id,
  coalesce(shop, 'Unknown')            AS shop,       -- fill
  nullif(trim(price), 'n/a')           AS price,      -- "n/a" becomes NULL
  coalesce(email, phone, 'none given') AS contact     -- first value that is not NULL
FROM bakery.bronze.orders_raw
WHERE order_id IS NOT NULL;                         -- drop
What if I change this?

Every option of dropna and fillna

ChangeEffect
dropna() with no argumentsDrops a row if any column is NULL. On a wide table this can remove most of your data.
dropna(how="all")Drops a row only if every column is NULL. Removes fully blank lines and nothing else.
dropna(subset=["order_id"])Looks only at the listed columns. The usual, safe form.
dropna(thresh=3)Keeps rows that have at least 3 non-NULL values.

Useful helpers

coalesce(a, b, c)

Returns the first of its arguments that is not NULL. The general-purpose filler.

nullif(a, b)

Returns NULL when a equals b, otherwise a. Turns a stand-in such as "n/a" into a real NULL.

isNull() / IS NULL

The only correct way to ask whether a value is missing.

Don't confuse these

NULL traps

NULL vs 0 vs ""

Three different things. NULL is unknown. 0 is a number. "" is text with no characters. Only NULL is skipped by averages.

= NULL vs IS NULL

= NULL never matches. IS NULL is the test. In PySpark, .isNull().

dropna any vs all

The default is "any": one NULL anywhere removes the row. "all" removes only rows that are entirely NULL.

fillna and types

fillna(0) touches only numeric columns and fillna("x") only text columns. A fill that seems to do nothing is usually a type mismatch.

Check yourself

Quiz

1. What does orders.dropna() with no arguments remove?

The default is how="any". It works on rows, not columns, and one NULL is enough.

2. A column holds 4, 2 and NULL. What is its average?

Aggregates skip NULLs: (4 + 2) / 2 = 3. Filling the NULL with 0 would have given 2.

3. Which SQL condition finds rows with no shop?

Comparing with = never matches NULL. An empty string is a different value from NULL.

4. In the demo, what did filling missing prices with 0 do to the average?

A NULL is skipped. A zero is a real value and pulls the average down.

5. What does coalesce(email, phone, 'none given') return?

coalesce walks its arguments left to right and returns the first non-NULL one.

Wrap up

Key takeaways

  • NULL means unknown. It is not zero and not empty text.
  • Decide per column: drop the row, fill a value, or leave the NULL.
  • Turn disguised values such as "n/a" into real NULLs first.
  • Test with IS NULL or isNull(). Comparisons with NULL are never true.
  • dropna defaults to "any". Always consider subset.
