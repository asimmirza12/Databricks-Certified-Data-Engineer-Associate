Union and union all

A join puts tables side by side. A union stacks them on top of each other. It sounds simpler, and it hides two traps that catch nearly everyone once.

The idea

Stack rows from two tables

A union takes two tables with the same columns and returns one table containing the rows of both. North shop's orders plus South shop's orders become all orders.

There are two questions to settle every time.

1. What happens to duplicate rows?

  • UNION ALL keeps everything. If the same row is in both tables, it appears twice.
  • UNION (also written UNION DISTINCT) removes duplicate rows from the result.

2. How are the columns lined up?

  • By position. The first column of one table goes over the first column of the other, whatever they are called. This is how SQL's UNION and PySpark's union() work.
  • By name. Columns called price are lined up with each other, wherever they sit. This is PySpark's unionByName().

And here is the first trap. In SQL, plain UNION removes duplicates. In PySpark, union() does not. The PySpark method behaves like SQL's UNION ALL.

Everyday analogy

Merging two guest lists. You and a friend each wrote a list for the same party. Stapling the two sheets together is UNION ALL: quick, and anyone you both invited is on it twice. Copying them onto a fresh sheet and skipping names already written is UNION. And if your list is "first name, surname" while your friend's is "surname, first name", stacking them by position puts surnames under first names. You must line them up by what each column means.

How it works

Stacking, with and without duplicates

Removing duplicates is not free. To know that two rows are the same, Spark has to bring equal rows together, which means a shuffle. UNION ALL does no such work: it simply reads one table and then the other. So use UNION ALL unless you really need duplicates removed.

Result

Code

Union in both languages

north = spark.table("bakery.silver.orders_north")
south = spark.table("bakery.silver.orders_south")

# By position, keeping duplicates. Same as SQL's UNION ALL.
# Safe only when both DataFrames have the same columns in the same order.
all_orders = north.union(south)

# By column name. Safe whatever the column order.
all_orders = north.unionByName(south)

# By name, and tolerate a column that only one side has. The gap is filled with NULL.
all_orders = north.unionByName(south, allowMissingColumns=True)

# Remove duplicate rows afterwards, to get what SQL's plain UNION gives.
unique_orders = north.unionByName(south).distinct()
-- Keep every row.
SELECT order_id, item, price FROM bakery.silver.orders_north
UNION ALL
SELECT order_id, item, price FROM bakery.silver.orders_south;

-- Remove duplicate rows. UNION and UNION DISTINCT mean the same.
SELECT order_id, item, price FROM bakery.silver.orders_north
UNION
SELECT order_id, item, price FROM bakery.silver.orders_south;

In SQL, always list the columns in the same order in both halves, as above. SELECT * on each side relies on the two tables happening to have matching column orders.

Each variation

SQL UNION ALLAll rows from both, duplicates included. Fast.
SQL UNIONDuplicate rows removed. Slower, because rows must be compared.

Join or union?

Union

Adds rows. The tables describe the same kind of thing: orders and more orders. The result is longer.

Join

Adds columns. The tables describe different things that are related: orders and shops. The result is wider.

Don't confuse these

Union traps

SQL UNION vs PySpark union()

SQL's UNION removes duplicates. PySpark's union() keeps them. The exam likes this one.

union() vs unionByName()

union() goes by position and ignores names. unionByName() goes by name and ignores position.

UNION vs UNION ALL

ALL means "all rows, duplicates too". Without ALL, duplicates are removed at a cost.

distinct vs dropDuplicates

distinct() compares whole rows. dropDuplicates(["order_id"]) can compare chosen columns only (lesson 03-10).

Check yourself

Quiz

1. Table A has 10 rows and table B has 8. Three rows are identical in both. How many rows does SQL UNION ALL return?

UNION ALL keeps everything: 10 + 8. Plain UNION would return 15.

2. In PySpark, what does df1.union(df2) do with duplicate rows?

The DataFrame union() behaves like SQL's UNION ALL. Add .distinct() to remove duplicates.

3. Two DataFrames have the same columns in different orders. Which method combines them correctly?

unionByName lines columns up by their names, so order does not matter.

4. In the demo, what did plain union() do with the second table's columns?

It paid no attention to names. The values went into whatever column sat in the same position.

5. Why is UNION ALL cheaper than UNION?

Finding duplicates requires bringing equal rows together, which is a shuffle. UNION ALL avoids it.

Wrap up

Key takeaways

  • A union stacks the rows of two tables. A join adds columns.
  • UNION ALL keeps duplicates. UNION removes them and costs more.
  • PySpark's union() keeps duplicates, like SQL's UNION ALL.
  • union() matches columns by position. unionByName() matches by name.
  • allowMissingColumns=True fills columns that one side lacks with NULL.
