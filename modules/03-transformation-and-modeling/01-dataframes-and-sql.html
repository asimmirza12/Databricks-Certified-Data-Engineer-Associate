DataFrames and SQL: two ways to say the same thing

The idea

One engine, two languages

A DataFrame is a table that you hold in a Python variable. You change it by calling methods on it, one after another: keep these columns, keep those rows, add up that column.

SQL describes the same kind of change as one sentence: SELECT these columns FROM that table WHERE some condition holds.

They are not rivals. Spark turns both into the same internal plan and runs it on the same engine. A query written in SQL is no faster or slower than the same query written with DataFrames. You pick whichever reads more clearly for the job, and you can mix them freely in one notebook.

The exam shows code in both. You need to be able to read a line of PySpark and recognise its SQL twin, and the other way round.

Everyday analogy

Ordering in a café. You can say it as one sentence: "A large oat-milk latte with one sugar, to take away." Or you can tap it into the kiosk step by step: latte, then large, then oat milk, then one sugar, then take away. The barista makes the same drink. SQL is the sentence. The DataFrame style is the kiosk.

Reading a bronze table


from pyspark.sql import functions as F

# Three ways to get a DataFrame from a Unity Catalog table. All give the same thing.
orders = spark.table("bakery.bronze.orders_raw")
orders = spark.read.table("bakery.bronze.orders_raw")
orders = spark.sql("SELECT * FROM bakery.bronze.orders_raw")

orders.printSchema()        # column names and types
display(orders.limit(10))   # look at a few rows in the notebook

# A small transformation, written with DataFrame methods.
north = (orders
    .filter(F.col("shop") == "North")      # keep North rows
    .select("item", "price")               # keep two columns
    .orderBy("price"))


-- The same thing in SQL.
SELECT item, price
FROM bakery.bronze.orders_raw
WHERE shop = 'North'
ORDER BY price;

  
You can cross between the two whenever it helps. A temporary view gives a DataFrame a name that SQL can use. It lasts only for your session and stores nothing.


# DataFrame -> SQL: give the DataFrame a name for this session.
north.createOrReplaceTempView("north_orders")

# SQL -> DataFrame: spark.sql returns a DataFrame you can keep working on.
dear = spark.sql("SELECT * FROM north_orders WHERE price > 3")
dear = dear.withColumn("price_with_tax", F.col("price") * 1.2)

  
Ways to refer to a column in PySpark: "price" where a plain name will do, and F.col("price") when you need to compare or calculate. orders.price and orders["price"] also work. You will see all of them.






  
What if I change this?

  
Details that trip beginners

  

    
ChangeEffect

    
Write the query in SQL instead of PySparkNo difference in speed or result. Spark builds the same plan.

    
Use = for a comparison in PySparkAn error. Python compares with ==. SQL compares with a single =.

    
Call .filter(...) and store nothingNothing changes. DataFrames are never altered in place: every method returns a new one, which you must keep in a variable.

    
Use .show() instead of display()show() prints plain text and works anywhere Spark runs. display() is a Databricks notebook extra with sorting and charts.

    
Leave out .limit() when looking at a huge tableThe notebook still shows only a sample, but Spark may read far more than it needs to.

    
Reuse a temporary view in another notebook or jobIt is not there. Temporary views belong to one session. Use a real view or table to share.

Don't confuse these

  
Look-alikes

  

    
filter vs where
In PySpark they are the same method under two names. Use either.

    
== vs =
PySpark compares with ==. SQL compares with =. Mixing them up is the commonest slip.

    
Temporary view vs view
A temporary view lives in your session only. A view is saved in a schema and others can query it (lesson 03-14).

    
DataFrame vs table
A DataFrame is a plan held in a variable while your code runs. A table is data saved in the catalog. A DataFrame disappears unless you write it.

  






  
Check yourself

  
Quiz

  

    

      1. The same query is written once in PySpark and once in SQL. Which runs faster?
      
      
      
      
Both go through the same optimiser and engine, so the work done is identical.

    

    

      2. Which PySpark line matches WHERE shop = 'North'?
      
      
      
      
filter chooses rows, and Python compares with a double equals sign.

    

    

      3. What does createOrReplaceTempView("north_orders") do?
      
      
      
      
A temporary view is only a name for the session. Nothing is stored, and other sessions cannot see it.

    

    

      4. After orders.filter(F.col("price") > 3) on a line by itself, what does orders contain?
      
      
      
      
DataFrame methods return a new DataFrame and never change the original. The filtered result was thrown away.

    

  






  
Wrap up

  
Key takeaways

  
    
    
  • PySpark DataFrames and SQL are two ways to write the same transformations.
    • 
    
  • Spark turns both into one plan, so there is no speed difference.
    • 
    
  • spark.table reads a table. spark.sql runs SQL and returns a DataFrame.
    • 
    
  • A temporary view lets SQL use a DataFrame for the length of a session.
    • 
    
  • DataFrame methods return new DataFrames. Always keep the result.
