Columns: add, drop, rename, split

Most of the work in a silver table is reshaping columns. Work out a total, throw away what nobody needs, give things sensible names, and break one overloaded column into several.

The idea

Four everyday moves

  • Add a column whose value is worked out from others. amount is price times qty.
  • Drop a column you do not want to carry forward, such as an internal code or a personal detail.
  • Rename a column so its name says what it holds. c_nm becomes customer_name.
  • Split one column that holds several facts into separate columns. "Ana Lopez" becomes a first name and a surname.

In PySpark each move is one method. In SQL they all happen in the SELECT list: you write out the columns you want the result to have, calculated and named as you wish.

Remember from lesson 03-01 that none of this changes the original DataFrame or table. Each step gives a new DataFrame. The stored table only changes when you write the result back.

Everyday analogy

Tidying a spreadsheet someone else made. You add a "total" column with a formula. You delete the column of scribbled notes. You retype the header "Col7" as "Delivery date". And you use "text to columns" to break "Leeds, LS1 4AB" into a city and a postcode. Four moves, and the sheet is usable.

How it works

A chain of small steps

The order of steps matters. You cannot use a column after dropping it, or by its old name after renaming it.

How splitting works

The split function cuts a piece of text wherever it finds a separator, and gives back a list of the pieces. A list in a column is an array. You then take the pieces you want by position, counting from 0. split("Ana Lopez", " ") gives ["Ana", "Lopez"]. Piece 0 is "Ana" and piece 1 is "Lopez".

Each move in PySpark and SQL


from pyspark.sql import functions as F

orders = spark.table("bakery.silver.orders")

shaped = (orders
    # ADD: a new column from a calculation. An existing name would be replaced.
    .withColumn("amount", F.col("price") * F.col("qty"))

    # ADD a fixed value: lit() turns a plain value into a column.
    .withColumn("currency", F.lit("GBP"))

    # SPLIT: cut on the space, then pick pieces by position (0 is the first).
    .withColumn("first_name", F.split("customer", " ").getItem(0))
    .withColumn("last_name",  F.split("customer", " ").getItem(1))

    # RENAME: old name first, new name second.
    .withColumnRenamed("qty", "quantity")

    # DROP: one or more columns. Dropping a name that does not exist is not an error.
    .drop("tmp_code", "customer"))

# Several at once.
shaped = orders.withColumns({"amount": F.col("price") * F.col("qty"), "currency": F.lit("GBP")})
shaped = orders.withColumnsRenamed({"qty": "quantity", "c_nm": "customer_name"})


-- In SQL the SELECT list does all four jobs.
SELECT
  order_id,
  split(customer, ' ')[0]   AS first_name,     -- split, then take piece 0
  split(customer, ' ')[1]   AS last_name,
  price,
  qty                       AS quantity,       -- rename with AS
  price * qty               AS amount,         -- add
  'GBP'                     AS currency
  -- tmp_code and customer are dropped simply by not listing them
FROM bakery.silver.orders;

-- Keep everything except a couple of columns.
SELECT * EXCEPT (tmp_code, customer) FROM bakery.silver.orders;

  
Those statements change the result of a query. To change the structure of a stored table itself, use ALTER TABLE:


ALTER TABLE bakery.silver.orders ADD COLUMN currency STRING;
ALTER TABLE bakery.silver.orders RENAME COLUMN qty TO quantity;
ALTER TABLE bakery.silver.orders DROP COLUMN tmp_code;

  
Renaming and dropping columns of a stored Delta table needs a table feature called column mapping to be enabled. Verify the requirement in the docs before relying on it.






  
What if I change this?

  
Behaviours worth knowing

  

    
ChangeEffect

    
withColumn with a name that already existsThe existing column is replaced, not duplicated. This is how you change a column in place.

    
withColumn("currency", "GBP") without litAn error. The second argument must be a column expression. Wrap plain values in F.lit().

    
drop a column that does not existNothing happens and no error is raised. A typo in a drop goes unnoticed.

    
withColumnRenamed with an old name that does not existNothing happens and no error is raised.

    
Use a column after dropping itAn error when the plan runs: the column cannot be found.

    
getItem(1) on a split that produced only one pieceSplitting "Madonna" on a space gives one piece, so there is no piece 1. You get NULL, or an error where the strict ANSI mode is on. The function get(array, 1) gives NULL in both cases.

    
Split on a character that has a special meaning, such as . or |The separator is a pattern, not plain text, so these need a backslash: "\\.".

    
Call withColumn hundreds of times in a loopThe plan grows very large and slow to prepare. Use one select or withColumns.

Don't confuse these

  
Column traps

  

    
withColumn vs withColumnRenamed
withColumn adds or replaces a column's values. withColumnRenamed changes only its name.

    
select vs drop
select names what to keep. drop names what to remove. Use whichever list is shorter and safer.

    
Query vs table
SELECT ... AS shapes the output of one query. ALTER TABLE changes the stored table for everyone.

    
split gives an array
split does not create columns by itself. It returns an array, and you pick elements out of it.

Quiz

  

    

      1. What does df.withColumn("price", F.col("price") * 2) do when price already exists?

      2. What does F.split("Ana Lopez", " ").getItem(1) return?
      
      
      
      
Positions count from 0. Item 0 is "Ana" and item 1 is "Lopez".

    

    

      3. What happens if you drop("tmp_cod") when the column is really called tmp_code?
      
      
      
      
drop silently ignores names it cannot find, so typos pass unnoticed.

    

    

      4. In the demo, what happened when you added amount after renaming qty?
      
      
      
      
Steps apply in order. After the rename, the expression must use the new name.

    

    

      5. Which adds a column with the same text in every row?
      
      
      
      
A plain value must be wrapped in lit to become a column expression.

  • withColumn adds or replaces. drop removes. withColumnRenamed renames.
    • 
    
  • split returns an array. Pick pieces by position, starting at 0.
    • 
    
  • In SQL, the SELECT list does all of it with expressions and AS.
    • 
    
  • drop and withColumnRenamed ignore names that do not exist.
