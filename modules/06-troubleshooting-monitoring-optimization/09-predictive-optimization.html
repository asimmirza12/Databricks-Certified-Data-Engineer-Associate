Predictive optimization

Delta tables need regular upkeep: compacting small files, deleting old ones and refreshing statistics. Predictive optimization does that upkeep for you, on the tables that need it, without you scheduling anything.

The idea

Table upkeep, on autopilot

Without help, a busy Delta table slowly gets worse. Many small writes leave many small files. Updates and deletes leave old files behind. Statistics used to skip files go stale. You would normally fix this by scheduling OPTIMIZE, VACUUM and ANALYZE yourself.

Predictive optimization runs those three operations automatically. Databricks watches how each table is used and runs the operation only when it expects a benefit. It also clusters tables that use liquid clustering, and picks keys for CLUSTER BY AUTO tables.

The main facts:

  • It works only on Unity Catalog managed tables, not external tables.
  • The docs say it is on by default. An account admin can change the account setting, and a catalog, schema or table can ENABLE, DISABLE or INHERIT it. By default each level inherits from the one above.
  • The work runs on serverless compute and is billed under a serverless jobs SKU.
  • You can see what it did in the system table system.storage.predictive_optimization_operations_history (Public Preview).
  • VACUUM keeps at least 7 days of old files, matching the default retention.
Everyday analogy

A cleaning service for the bakery. Instead of putting "clean the ovens" on the calendar every Tuesday whether they need it or not, a cleaner checks each oven and cleans the ones that are actually dirty. They only work in the shop's own kitchens (managed tables), not in kitchens you rent elsewhere (external tables).

How it works

Settings flow down, work flows to the tables that need it

Each level inherits unless it sets ENABLE or DISABLE itself.

Code

Control it and check what it did

-- Turn it on for the whole bakery catalog, off for one sandbox schema
ALTER CATALOG bakery ENABLE PREDICTIVE OPTIMIZATION;
ALTER SCHEMA bakery.sandbox DISABLE PREDICTIVE OPTIMIZATION;

-- Go back to following the parent's setting
ALTER SCHEMA bakery.sandbox INHERIT PREDICTIVE OPTIMIZATION;

-- See the effective setting on an object
DESCRIBE SCHEMA EXTENDED bakery.gold;

-- What did it run on the bakery catalog in the last week?
SELECT start_time, table_name, operation_type, operation_status, usage_quantity
FROM system.storage.predictive_optimization_operations_history
WHERE catalog_name = 'bakery'
  AND start_time >= current_date() - INTERVAL 7 DAYS
ORDER BY start_time DESC;

The history table is in Public Preview and rows can take several hours to appear. Check its column names in the docs before building a dashboard on it.

What if I change this?

Settings and their effects

ChangeEffect
Catalog set to INHERITFollows the account setting.
Schema set to DISABLE under an enabled catalogTables in that schema are not maintained (unless a table enables it).
Account disabled, catalog set to ENABLEThat catalog is still maintained. An explicit setting wins over the parent.
Table is externalNever covered. Schedule OPTIMIZE and VACUUM yourself.
Table uses CLUSTER BY AUTONeeds predictive optimization to choose keys and cluster.
Table uses ZORDERPredictive optimization's OPTIMIZE does not Z-order.

OPTIMIZE

Compacts small files and clusters liquid-clustered tables.

VACUUM

Deletes files no longer used by the table, older than the retention period.

ANALYZE

Refreshes statistics so queries skip files and plan joins well.

Don't confuse these

Predictive optimization traps

Managed only

External tables are never covered.

Three operations

OPTIMIZE, VACUUM and ANALYZE. Not ZORDER.

Inheritance

Account, then catalog, then schema, then table. An explicit setting beats the parent.

Not free

It runs on serverless compute and is billed.

Check yourself

Quiz

1. Which operations does predictive optimization run?

It also clusters liquid-clustered tables as part of OPTIMIZE.

2. Which table is never covered?

Only Unity Catalog managed tables are covered.

3. The account is enabled. Catalog bakery is INHERIT, schema sandbox is DISABLE. What happens to tables in bakery.sandbox?

The schema's own DISABLE overrides what it would inherit.

4. In the demo, after a week on an external table, what did the health panel show?

Nothing runs on external tables, whatever the settings say.

Wrap up

Key takeaways

  • Predictive optimization runs OPTIMIZE, VACUUM and ANALYZE when they help.
  • Unity Catalog managed tables only; external tables need manual upkeep.
  • Set at account, catalog, schema or table with ENABLE, DISABLE or INHERIT.
  • Runs on serverless compute; see what it did in the operations history system table.
