A tour of the Spark UI: jobs, stages, tasks

When a single task in your job is slow, the next place to look is inside Spark itself. The Spark UI shows how your code was split into pieces of work and how long each piece took.

The idea

Your code, broken into jobs, stages and tasks

The Spark UI is a set of web pages that show what Spark did with your code. It uses three nested words:

  • A Spark job starts each time your code asks for a result, such as writing a table or counting rows (an action).
  • Each Spark job is split into stages. A new stage begins wherever data has to be shuffled between machines.
  • Each stage is split into Spark tasks, one per partition of data. Tasks in a stage run in parallel on the executors.

Careful: a Spark job is not a Lakeflow job, and a Spark task is not a job task. One notebook task in Lakeflow Jobs can start many Spark jobs.

To open it on classic compute, go to the compute's details page and choose the Spark UI tab. On serverless compute the Spark UI is not available; you use the query profile instead.

Everyday analogy

A catering order at the bakery. The order (Spark job) is "200 sandwiches". It happens in stages: bake the bread, then slice and fill. Between stages, trays have to be carried across the kitchen (the shuffle). Inside each stage, each baker handles one tray (a task). The Spark UI is the kitchen's whiteboard showing every tray and how long it took.

How it works

One action, two stages, many tasks

Stage 1 has one task per input partition. After the shuffle, stage 2 has one task per shuffle partition.

Code

Code that makes stages

# Nothing runs yet: these are transformations (lazy)
sales = spark.read.table("bakery.silver.sales")
big   = sales.filter("amount > 10")                 # narrow: stays in the same stage
daily = big.groupBy("store_id", "sale_date").sum("amount")   # wide: needs a shuffle

# This action starts a Spark job. In the Spark UI expect a read stage,
# a shuffle, and an aggregate stage.
daily.write.mode("overwrite").saveAsTable("bakery.gold.daily_store_sales")

# See the plan without running it. "Exchange" marks each shuffle.
daily.explain()

In the Spark UI, the SQL tab shows the same plan as a picture, with an Exchange box at each shuffle and metrics on each step.

What if I change this?

Changes and what you see in the Spark UI

ChangeEffect
Add a groupBy or joinOne more shuffle, so one more stage.
Add a filter or a new columnNo new stage. It runs inside the existing one.
More input filesMore tasks in the read stage.
Change spark.sql.shuffle.partitionsChanges the number of tasks after a shuffle (default 200).
AQE coalescing onTiny shuffle partitions are merged at run time, so fewer, fuller tasks.
Restart the computeThe Spark UI now shows the new session; the old history is not there.

Databricks suggests an order: start with the Jobs timeline, find the longest stage, then check it for skew or spill, then check whether it is mostly reading or writing data.

Real life

The Spark UI in practice

ScenarioWhat happensFix
A notebook task takes 40 minutesOne stage takes 35 of themOpen that stage and read its summary metrics
You cannot find the Spark UI on a serverless notebookIt is not available on serverlessUse the query profile from the cell or from query history
Yesterday's slow run is gone from the Spark UIThe compute was restartedLook at the run's own page, or reproduce the run
A stage has 200 tiny tasks on a small tableTask startup costs more than the workKeep AQE on, or lower the shuffle partitions
Don't confuse these

Spark UI traps

Spark job vs Lakeflow job

A Spark job is one action inside your code. A Lakeflow job is the scheduled workflow.

Spark task vs job task

A Spark task handles one partition. A job task is one notebook, query or pipeline.

Stage boundary = shuffle

New stages start where data moves between machines.

Serverless

No Spark UI. Use the query profile.

Check yourself

Quiz

1. What usually starts a new stage inside a Spark job?

Stage boundaries sit where data must move between machines.

2. How many tasks does a stage normally have?

200 is only the default number of shuffle partitions, and AQE can change it.

3. You use serverless compute. Where do you look instead of the Spark UI?

Serverless does not offer the Spark UI.

4. In the demo, what changed when you picked "join with stores, groupBy, write"?

Each wide step added a shuffle and so a stage.

Wrap up

Key takeaways

  • Action makes a Spark job; shuffles split it into stages; partitions split stages into tasks.
  • Open it from the compute details page, Spark UI tab. Serverless uses the query profile.
  • Start with the Jobs timeline, then the longest stage, then its summary metrics.
  • Spark jobs and tasks are not Lakeflow jobs and tasks.
