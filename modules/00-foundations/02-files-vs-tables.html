Files vs tables

Data arrives as files. People want tables. Most of data engineering happens in the gap between the two.

00-01 What is data engineering?
The idea

A file holds anything. A table has rules.

A file is a named lump of data. The computer storing it does not care what is inside. It could be orders, a photo or nonsense. Nothing checks it.

A table is data arranged in rows and columns, like a spreadsheet. Each row is one thing, such as one order. Each column is one fact about it, such as the price.

What makes a table special is its schema: the list of column names and the data type of each one. A data type says what kind of value is allowed: a whole number, text, a date and so on. The table refuses anything that does not fit.

Everyday analogy

A shoebox of receipts versus an accounts book. You can throw anything into the shoebox: receipts, a bus ticket, a shopping list. Finding last month's total means reading every scrap. The accounts book has ruled columns for date, shop and amount. You cannot write "three pounds-ish" in the amount column. Because of that rule, adding up the column takes seconds.

How it works

A schema turns text into a table

The file below is plain text. To use it as a table, something has to read each line, split it into columns and check each value against the schema.

In the file, 4.50 is three characters of text. In the table it is a number you can add up.

A secret worth knowing early: on Databricks, a table is still stored as files underneath. The table is those files plus a schema plus rules about how they change. Lesson 00-08 shows how.

The file never complains, so problems are found late, when someone tries to use the data. The table complains at once, so problems are found early.

  






  
Code

  
Making a table, and reading a file as a table

  
In SQL, you state the schema when you create the table.


-- The schema: three columns, each with a name and a data type.
CREATE TABLE bakery.silver.orders (
  order_id INT,            -- whole numbers only
  shop     STRING,         -- any text
  price    DECIMAL(10,2)   -- numbers with 2 digits after the point
);

INSERT INTO bakery.silver.orders VALUES (106, 'North', 3.50);   -- accepted

-- Because price is a number, this just works:
SELECT SUM(price) FROM bakery.silver.orders;

  
In Python, you give a schema when reading a file, so Spark knows how to treat each column.


# Read a text file AS IF it were a table, using a schema we supply.
orders = (spark.read
    .format("csv")
    .option("header", "true")                                   # first line holds column names
    .schema("order_id INT, shop STRING, price DECIMAL(10,2)")   # what each column should be
    .load("/Volumes/bakery/landing/till_files/orders/"))

orders.printSchema()   # shows the column names and types Spark is using






  
What if I change this?

  
Reading a file with different settings

  

    
ChangeEffect

    
Leave out .schema(...) when reading a CSV fileEvery column is read as text. 4.50 is the characters "4.50", not a number, until you convert it.

    
Leave out the header optionThe first line is treated as data, and columns get placeholder names such as _c0, _c1.

    
Give a schema, but a value does not fit (words in price)By default the read carries on and that value becomes NULL, meaning "no value". Nothing warns you. Later lessons show stricter settings.

    
Insert a value of the wrong type into a tableThe table refuses the insert with an error. The bad row never gets in.

    
Add a column to the file that the table does not haveThe file accepts it. The table does not, unless you choose to allow schema changes (Module 02).

Three shapes of data

  

    
Structured
Structured data already fits rows and columns. Example: a sales spreadsheet.

    
Semi-structured
Semi-structured data has labels but a loose shape. One record may have fields another lacks. Example: a web order with an optional gift note.

    
Unstructured
Unstructured data has no rows or columns at all. Example: photos of receipts, voice recordings, PDF contracts.

  






  
Real life

  
Where files and tables cause trouble

  

    
ScenarioWhat happensFix

    
A shop types "n/a" in the price column of its daily fileThe file is accepted. The price becomes NULL when read, and the daily total is too low.Count NULLs after loading and alert if there are any

    
The total of a column comes out as an error or as textThe column was read as text because no schema was givenSupply a schema, or convert the column to a number

    
Two people edit the same shared fileOne person's changes overwrite the other'sLoad the data into a table, which handles many writers safely

    
A supplier renames a column from price to unit_priceYour price column is suddenly all NULLCheck that expected columns exist before loading

  






  
Don't confuse these

  
One word, two meanings

  

    
Schema vs schema
"Schema" can mean the columns and types of one table. On Databricks it also means a container that holds tables, like a folder. In bakery.silver.orders, silver is a schema in that second sense. Lesson 00-09 covers it.

    
NULL vs zero vs empty
NULL means "we do not know". It is not 0 and not empty text. A NULL price is left out of a total, not counted as zero.

    
Table vs file underneath
You query a table by name. The files that hold its data are an internal detail. Never edit those files by hand.

    
STRING "4.50" vs number 4.50
They look the same on screen. Only the number can be added, averaged or compared properly.

  






  
Check yourself

  
Quiz

  

    

      1. What is a schema, in the sense used for a single table?
      
      
      
      
The schema is the table's rulebook: which columns exist and what kind of value each may hold.

    

    

      2. In the demo, what happened when you appended "107,South,three pounds" to the file?
      
      
      
      
A file has no rules. The problem only showed up later, when the total was calculated.

    

    

      3. You read a CSV file with a schema, and one price contains words. By default, what do you get for that value?
      
      
      
      
The default is forgiving: the value that does not fit becomes NULL and the read continues. That is convenient and also risky, because it is silent.

    

    

      4. Which is an example of unstructured data?
      
      
      
      
Photos have no rows or columns. The table and the CSV file are both structured.
