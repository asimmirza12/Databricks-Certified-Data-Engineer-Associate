What is data engineering?

Before any tool, you need the big picture: what a data engineer does all day, and why anyone pays for it.

The idea

Moving data from where it is made to where it is used

Every business creates data all day long. A till records a sale. A website records an order. A supplier emails a price list. Each of these lives in a different place and looks different.

People in the business want answers: "How much did we sell yesterday?" "Which shop is running low on flour?" They cannot answer those questions while the data is scattered and messy.

Data engineering is the work of collecting that data, storing it safely, cleaning it up and delivering it in a shape people can use. The person who does it is a data engineer. The thing they build is called a data pipeline: a set of steps that run again and again, without anyone clicking buttons.

Everyday analogy

Think of the water supply to your home. Rain falls in many places. Someone collects it, stores it in a reservoir, filters it and pipes it to your tap. You only turn the tap. A data engineer is the water engineer. The analyst reading a sales chart is the person filling a glass. Nobody thinks about the pipes until the water comes out dirty, or does not come out at all.

How it works

The four steps of every pipeline

Our example for this lesson is a made-up bakery chain with two shops, North and South. Follow the dots from top to bottom.

The places data comes from are called sources. Everything below them is the pipeline.

1 · Ingest

Ingestion means bringing data in from a source. Nothing is changed yet. You just make a copy.

2 · Store

The raw copy is kept somewhere cheap and safe. If you make a mistake later, you can start again from it.

3 · Transform

Transformation means changing data to make it useful: removing duplicates, fixing typos, adding things up.

4 · Serve

The finished data is handed to people and programs: a sales chart, a stock report, a forecasting model.

Two more jobs wrap around these four. Orchestration means running the steps in the right order at the right time. Governance means controlling who is allowed to see which data.

Code

The same pipeline as real code

You do not need to understand every line yet. Later modules teach each part slowly. For now, match each block to a step in the diagram. The first example is PySpark, which is Python for working with large data.

from pyspark.sql import functions as F

# 1 + 2. INGEST and STORE: read the till files and keep an untouched copy.
# "header" tells Spark the first line of each file holds the column names.
raw_orders = (spark.read
    .format("csv")
    .option("header", "true")
    .load("/Volumes/bakery/landing/till_files/orders/"))

raw_orders.write.mode("append").saveAsTable("bakery.bronze.orders_raw")

# 3. TRANSFORM: fix the three problems you saw in the demo.
clean_orders = (spark.table("bakery.bronze.orders_raw")
    .withColumn("shop", F.initcap(F.trim("shop")))             # "north " becomes "North"
    .withColumn("price", F.col("price").cast("decimal(10,2)"))  # text becomes a number
    .dropDuplicates(["order_id"])                             # the same order only once
    .filter(F.col("price").isNotNull()))                      # leave out orders with no price

clean_orders.write.mode("overwrite").saveAsTable("bakery.silver.orders")

The last step is often written in SQL, the standard language for asking questions of tables.

-- 4. SERVE: one row per shop, ready for a sales chart.
CREATE OR REPLACE TABLE bakery.gold.sales_by_shop AS
SELECT shop, SUM(price) AS total_sales
FROM bakery.silver.orders
GROUP BY shop;

The words bronze, silver and gold in the table names are a common way to label raw, cleaned and finished data. Lesson 00-10 explains it.

What if I change this?

Small choices, big effects

ChangeEffect
Skip the cleaning stepThe report still appears, but totals are wrong. Duplicates are counted twice and one shop shows up under two spellings.
Do not keep a raw copyYou save a little storage. But if your cleaning rule had a bug, the original data is gone and you cannot redo it.
Run once a night instead of every few minutesCheaper and simpler. The report is up to a day old. Fine for monthly sales, not fine for "are we out of bread right now?"
Run the steps by hand instead of on a scheduleWorks until the person is on holiday. Then nothing updates and nobody notices for days.
Use overwrite instead of append on the raw tableEach run replaces the history with only the latest files. Yesterday's raw data is lost.
Compare

ETL or ELT: the same steps in a different order

You will see these two short names everywhere. E is Extract (take data out of the source). T is Transform. L is Load (put data into your storage). The only difference is the order.

ETLELT
OrderExtract, Transform, LoadExtract, Load, Transform
Where cleaning happensBefore the data reaches your storageAfter the raw data is already stored

If a cleaning rule was wrongGo back to the source and extract againRerun the transform on the raw copy

Who does what on a data team

Data engineer

Builds and looks after the pipelines. Makes sure data arrives, is correct and is on time.

Data analyst

Uses the finished tables to answer business questions with charts and reports.

Data scientist

Uses the same tables to build models that predict things, such as next week's bread sales.

Don't confuse these

Words that sound alike

pipeline vs Pipeline

In general, a pipeline is any chain of data steps. On Databricks, "pipeline" can also mean one specific product, Lakeflow Spark Declarative Pipelines. Read the question to see which is meant.

Ingest vs transform

Ingesting copies data in without changing it. Transforming changes it. If a question says "land the raw data", it is about ingestion.

ETL vs ELT

Same three letters. In ELT the raw data is loaded first and cleaned afterwards, so a raw copy always exists.

Pipeline vs job

The pipeline is the work to be done. A job is what runs that work on a schedule and retries it when it fails.

Check yourself

Quiz

1. Which sentence best describes data engineering?

Charts are the analyst's work and predictions are the data scientist's. The engineer builds the pipelines that both of them depend on.

2. In the demo, what happened when you skipped the cleaning step?

Bad data rarely announces itself. The report looked normal, which is exactly why cleaning and checks matter.

3. Why keep an untouched raw copy of the data?

The raw copy is your safety net. Raw data is usually slower and harder to use, so analysts get the cleaned tables.

4. What is the difference between ETL and ELT?

Both do all three steps. Only the order changes: in ELT the data is stored raw first and cleaned afterwards.

Wrap up

Key takeaways

  • Data engineering moves data from where it is made to where it is used.
  • A pipeline has four steps: ingest, store, transform, serve.
  • Pipelines run again and again on their own. New data waits for the next run.
  • Keep a raw copy. Clean a copy of it, never the original.
  • Wrong data is worse than late data, because nobody notices it.
