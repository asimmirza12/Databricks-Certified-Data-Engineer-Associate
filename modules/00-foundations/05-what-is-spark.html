What is Apache Spark?

Spark is the engine under the bonnet of Databricks. It handles data too big for one computer by sharing the work between many.

The idea

Many computers working as one

A laptop can sort a spreadsheet of a few thousand rows. It cannot sort ten billion rows. The data does not fit in its memory, and it would take days.

Apache Spark is free, open-source software that solves this. It cuts the data into chunks and hands the chunks to a group of computers that work at the same time. Such a group is called a cluster.

Three words describe how it is organised:

  • The driver is the one computer in charge. It reads your code, makes a plan and hands out work.
  • The executors are the workers. They do the actual reading, filtering and adding up.
  • A partition is one chunk of the data. One executor works on one partition at a time.
Everyday analogy

A restaurant kitchen with a big order. A table orders 400 sandwiches. The head chef (driver) does not make them. The chef splits the order into trays of 50 (partitions) and gives each tray to a line cook (executor). Eight cooks finish far sooner than one. The chef only collects the finished trays and hands the order over.

How it works

The driver plans, the executors work

Blue dots are tasks going out. Green dots are results coming back. A task is "do this step on this one partition".

Spark is lazy, on purpose

When you write a step such as "keep only North shop orders", Spark does not do it straight away. It writes the step into a plan and waits. This is called lazy evaluation.

Steps that only add to the plan are called transformations. Steps that ask for a result, such as "count the rows" or "save the table", are called actions. Only an action makes Spark run the plan. Waiting lets Spark see the whole plan first and find the cheapest way to do it.

Code

Transformations build the plan. An action runs it.

In Spark, a table you are working with in code is called a DataFrame. Think of it as a table held by the cluster, not by your laptop.

from pyspark.sql import functions as F

orders = spark.table("bakery.silver.orders")       # nothing is read yet

north = orders.filter(F.col("shop") == "North")   # transformation: added to the plan
slim  = north.select("shop", "price")             # transformation: added to the plan

slim.explain()         # prints the plan Spark has built. Still nothing has run.

n = slim.count()       # ACTION: now the executors read, filter and count
slim.show(5)           # ACTION: runs the plan again to fetch 5 rows

The same work can be written in SQL. Spark turns both into the same plan, so neither is faster than the other.

SELECT COUNT(*) FROM bakery.silver.orders WHERE shop = 'North';
What if I change this?

More workers, more partitions, more actions

ChangeEffect
Add more executorsFaster, until there are as many executors as partitions. After that the extra ones have nothing to do, and you pay for them anyway.
One partition is much bigger than the othersThe whole job waits for that one. Adding executors does not help. This problem is called skew (Module 06).
Cut the data into thousands of tiny partitionsThe driver spends more time handing out tasks than the executors spend working.
Call two actions on the same DataFrameThe plan runs twice, from the start, unless you ask Spark to keep the result.
Use .collect() on a huge DataFrameEvery row is sent to the driver, a single computer. It can run out of memory and crash.

Don't confuse these

Pairs that get mixed up

Spark vs Databricks

Spark is the open-source engine. Databricks is a company and a platform that runs Spark for you and adds storage, security and tools around it.

Driver vs executor

One driver plans and coordinates. Many executors do the work. Results that you "collect" land on the driver.

Transformation vs transformation

In lesson 00-01, "transform" meant the cleaning stage of a pipeline. In Spark, a "transformation" is one lazy step such as filter. Same word, different size.

Spark partition vs table partition

A Spark partition is a chunk of data being worked on in memory. A partitioned table is a way of arranging stored files into folders. They are separate ideas.

Check yourself

Quiz

1. What is the driver's job?

The driver is the coordinator. The executors do the heavy work, and storage is a separate thing altogether.

2. Which of these makes Spark actually run?

count is an action: it needs a real answer. The other two are transformations that only extend the plan.

3. A job has 8 equal partitions. You go from 8 executors to 12. What happens to the run time?

With 8 partitions, only 8 executors can be busy at once. The extra 4 wait with nothing to do.

4. In the first experiment, why did the skewed job stay slow with many executors?

A partition is handled by one executor. If one partition is huge, that single executor sets the finish time.

Wrap up

Key takeaways

  • Spark splits data into partitions and works on them in parallel.
  • One driver plans. Many executors work.
  • Transformations are lazy. Only an action runs the plan.
  • More executors help only while there are partitions to share out.
  • Spark is the engine. Databricks is the platform that runs it.
