File formats: CSV, JSON, Parquet and friends

The same orders can be written to disk in very different ways. The way you choose decides how big the file is and how fast it can be read.

The idea

A format is a set of rules for writing data into a file

A file format is an agreement about how the data inside a file is laid out. The part of the file name after the dot usually tells you the format: .csv, .json, .parquet.

Some formats are plain text that a person can open and read. Others are written for machines: smaller and faster, but unreadable to the eye.

The biggest difference is the direction the data is stored in. Row-based formats write one whole record after another. Columnar formats write all the values of one column together, then the next column.

Everyday analogy

A class register. Row-based is one index card per pupil, with name, age and grade on each card. To find the average grade you must pick up every card. Columnar is three lists: all the names, all the ages, all the grades. For the average grade you read only the grades list and ignore the rest.

How it works

Reading one column from each kind of file

The question is "what is the total price?". Only the price column is needed. Watch how much each reader has to touch.

With 3 columns the saving is small. Real tables often have 50 or more columns, and most questions use only a few of them.

Columnar files have a second advantage. Values in one column look alike (many "North", many "South"), so they squash down well. Making data smaller this way is called compression.

Code

  
Reading and writing each format

  
In Spark the pattern is always the same: name the format, set a few options, give the path.


path = "/Volumes/bakery/landing/till_files/"

# CSV: plain text, values separated by commas. No types inside the file.
csv_orders = (spark.read.format("csv")
    .option("header", "true")    # the first line holds the column names
    .load(path + "orders_csv/"))

# JSON: plain text, every value carries its label. By default: one record per line.
json_orders = spark.read.format("json").load(path + "orders_json/")

# Parquet: columnar, compressed, and the schema is stored inside the file.
# No header or type options are needed.
parquet_orders = spark.read.format("parquet").load(path + "orders_parquet/")

# Converting is just: read one format, write another.
csv_orders.write.format("parquet").mode("overwrite").save(path + "orders_converted/")

  
On Databricks you rarely save plain Parquet yourself. You save a table, and the table stores its data as Parquet files for you, plus a log of changes. That combination is called Delta Lake, the subject of lesson 00-08.






  
What if I change this?

  
Options that matter when reading files

  

    
ChangeEffect

    
CSV: add .option("inferSchema", "true")Spark looks through the data and guesses the types, so numbers become numbers. It costs an extra pass over the files, and a guess can be wrong.

    
CSV: add .option("sep", ";")Values are split on semicolons instead of commas. Needed for files from countries that write prices as 4,50.

    
JSON: the file is "pretty-printed", one record spread over many linesThe default reader expects one record per line and cannot make sense of it. Add .option("multiLine", "true").

    
Parquet: ask for only two columns with .select(...)Only those two columns are read from storage. With CSV or JSON, the whole file is read anyway.

    
Open a Parquet file in a text editorYou see unreadable symbols. It is a binary format, made for programs, not people.

Which shape of data fits which format

  

    
Structured
CSV, Parquet, ORC and Avro all hold tidy rows and columns.

    
Semi-structured
JSON is the usual choice. Records can differ from one another and can contain lists and sub-records.

    
Unstructured
Images, audio and PDFs have their own formats (.png, .mp3, .pdf). They are stored as whole files, not as rows.

Don't confuse these

  
Formats that sound alike

  

    
Parquet vs Delta
Parquet is a file format. Delta is a table format: Parquet files plus a log that records every change. A folder of Parquet files alone is not a Delta table.

    
JSON vs JSON Lines
A JSON Lines file holds one complete record on each line. That is what Spark's JSON reader expects by default. One big record or list spread over many lines needs multiLine.

    
Stored schema vs guessed schema
Parquet and Avro carry their schema inside the file, so it is exact. For CSV, any schema is supplied by you or guessed by the reader.

    
Row-based vs columnar
Row-based is good for writing one record at a time. Columnar is good for reading a few columns from many records. Analytics is mostly the second.

  






  
Check yourself

  
Quiz

  

    

      1. A report needs 2 columns out of 60. Which format lets the reader skip the other 58?
      
      
      
      
Parquet is columnar, so each column is stored separately and unneeded ones are never read.

    

    

      2. Which of these formats stores no data types at all?
      
      
      
      
A CSV file is only text separated by commas. Whether "4.50" is a number is decided by whoever reads it.

    

    

      3. In the demo, why was the JSON file the largest?
      
      
      
      
CSV writes the column names once, in the header. JSON writes them again in every single record.

    

    

      4. What is the relationship between Parquet and Delta?
      
      
      
      
Delta builds on Parquet. The data files are Parquet. The log is what turns a folder of files into a reliable table.

    

  






  
Wrap up

  
Key takeaways

  
    
    
  • A file format is the set of rules for how data is written inside a file.
    • 
    
  • CSV and JSON are readable text. They are large and slow to query.
    • 
    
  • Parquet is columnar and compressed, and it carries its own schema.
    • 
    
  • Columnar formats let a query read only the columns it needs.
    • 
    
  • Data usually arrives as CSV or JSON and is stored as Parquet inside tables.
