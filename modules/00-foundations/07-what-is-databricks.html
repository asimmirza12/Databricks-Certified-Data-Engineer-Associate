The idea

One place to store, process and control data

Running Spark yourself is hard. You would have to rent computers, install software on each one, connect them to storage, keep them secure and switch them off afterwards.

Databricks is a cloud platform that does all of that for you. You log in through a web browser and find three things you will use every day:

  • A workspace: the website itself. It holds your code, your jobs and your team's work, organised in folders.
  • Compute: the computers that run your code. You switch them on when needed and pay while they are on.
  • Notebooks: documents made of small boxes called cells. Each cell holds some code or some notes. You run a cell and see the result right under it.

Your data is not stored "in Databricks". It stays in cloud object storage (lesson 00-06). Databricks reads it from there and writes it back.

Everyday analogy

A shared commercial kitchen. The building, with its door key and your labelled shelf, is the workspace. The ovens are compute: they cost money only while they are on, and you pick a small or a large one. A notebook is your recipe card, where you carry out one step at a time and taste as you go. The pantry in the next room, which stays stocked when the ovens are off, is cloud storage.

How it works

From your browser to your data

Attaching a notebook

A notebook by itself is only text. To run it, you attach it to compute. The compute then remembers what your cells have done so far, such as variables you created. That memory is lost when the compute stops. Data you saved into tables is not lost, because tables live in storage.

Code

What a notebook looks like

Each block below is one cell. A notebook has a main language, and a first line starting with % switches the language for a single cell. Those lines are called magic commands.

# Cell 1 (Python). The variable `spark` already exists in every notebook.
orders = spark.table("bakery.silver.orders")
display(orders)          # shows the rows as a table you can sort and chart
%sql
-- Cell 2 (SQL), in the same notebook.
SELECT shop, SUM(price) AS total_sales
FROM bakery.silver.orders
GROUP BY shop;
%md
## Cell 3 (Markdown)
Notes for the next reader. This cell shows formatted text and runs no code.
%run ./shared_settings
# Cell 4: runs another notebook, so its variables and functions can be used here.
What if I change this?

Everyday choices in the workspace

ChangeEffect
Leave classic compute running overnight with auto-stop offYou pay for every idle hour. Auto-stop (called automatic termination) switches it off after a quiet period you choose.
Stop or restart the computeVariables from earlier cells are gone, so you run those cells again. Tables you saved are untouched.
Run cells out of orderA cell that needs a variable from an earlier cell fails, because that variable does not exist yet.
Choose serverless instead of classicNothing to size or configure, and it starts in seconds, not minutes. In return you have fewer settings to tune.
Run a nightly job on all-purpose computeIt works, but that kind of compute is meant for people working by hand. Scheduled work belongs on jobs compute or serverless (Module 01).

Don't confuse these

Easy mix-ups

Workspace vs storage

The workspace keeps code and settings. Your data sits in cloud object storage. Deleting a notebook does not delete a table.

Notebook state vs saved data

Variables live in the compute's memory and vanish when it stops. Tables live in storage and stay.

All-purpose vs jobs compute

All-purpose is for interactive work by people. Jobs compute exists only for the length of one scheduled run.

Cluster vs SQL warehouse

Both are compute. A cluster runs notebooks in any language. A SQL warehouse is built to run SQL.

Check yourself

Quiz

1. Where is the data in your tables actually kept?

Compute only processes data. The files behind every table sit in storage and outlive any compute.

2. In the demo, you stopped the compute after running all three cells. What survived?

Variables are held in the compute's memory and are lost. The table was written to storage, so it is still there.

3. What does the %sql line at the top of a notebook cell do?

A magic command applies to its own cell only. The other cells keep the notebook's main language.

4. Which compute is intended for a person exploring data by hand in a notebook, with settings they chose themselves?

All-purpose compute stays up for interactive work. Jobs compute starts and stops with one scheduled run.

Wrap up

Key takeaways

  • Databricks is a cloud platform that runs Spark and manages the pieces around it.
  • The workspace holds your code. Compute runs it. Storage holds the data.
  • A notebook must be attached to compute before its cells can run.
  • You pay for compute while it is on, so let it stop when idle.
  • Stopping compute loses variables, never tables.
