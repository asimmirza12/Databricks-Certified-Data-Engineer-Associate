The Databricks CLI: install, log in, basic commands

The CLI lets you work with Databricks by typing commands instead of clicking. It is how bundles are deployed, and it is what a CI system uses, because a robot cannot click buttons.

00-07 What is Databricks?
The idea

Talking to Databricks in a terminal

A terminal is a window where you type commands and read the replies. A CLI (command-line interface) is a program you use that way. The Databricks CLI is a program called databricks.

Using it takes three steps:

  1. Install it on your computer, for example with Homebrew on a Mac. Check it with databricks -v. Bundles need a recent version (0.205.0 or above is the "new" CLI; individual bundle features may need newer).
  2. Log in with databricks auth login --host <workspace URL>. A browser window opens, you sign in, and the CLI saves a configuration profile: a named set of connection details in the file ~/.databrickscfg.
  3. Run commands. They are grouped by area: databricks jobs ..., databricks clusters ..., databricks fs ..., databricks bundle .... Add -p <profile> to choose which workspace.

Signing in through the browser is for people. Automated systems sign in as a service principal (a non-human identity) using OAuth machine-to-machine credentials, covered in lesson 05-10.

Everyday analogy

Phoning the bakery instead of walking in. Installing the CLI is buying a phone. Logging in is saving the shop's number in your contacts (the profile). Each command is a short call: "how many jobs do you have?" With several shops saved, you pick which one to call.

How it works

From command to workspace

The profile tells the CLI which workspace to call and how to prove who you are.

Command groups you will meet

auth

login, profiles, describe: sign in and see who you are.

jobs, pipelines, clusters

List, get, start and change objects in the workspace.

fs and workspace

Files in volumes, and notebooks and folders in the workspace.

bundle

init, validate, deploy, run, destroy. Next lesson.

Code

  
Install, log in, look around


# macOS or Linux with Homebrew (other methods: see the install page)
brew install databricks/tap/databricks
databricks -v                                  # prints the version

# sign in through the browser; saves a profile
databricks auth login --host https://dev-bakery.cloud.databricks.com
databricks auth login --host https://prod-bakery.cloud.databricks.com -p prod
databricks auth profiles                       # list saved profiles

# everyday commands
databricks jobs list                           # uses the DEFAULT profile
databricks jobs list -p prod -o json           # prod workspace, JSON output
databricks fs ls dbfs:/Volumes/bakery/bronze/landing
databricks jobs run-now 123456                 # start a job by ID
databricks jobs --help                         # see every jobs command

  
Every command accepts --help. Newer Homebrew versions may ask you to trust the Databricks tap first; follow the install page.

Don't confuse these

  
CLI traps

  

    
Profile vs target
A profile is a saved login in ~/.databrickscfg. A target is an environment in databricks.yml.

    
New vs legacy CLI
Bundles need the new CLI (0.205+). The old Python one has no bundle group.

    
-p and -t
-p picks a profile. -t picks a bundle target.

    
Secrets
Never commit ~/.databrickscfg or tokens to Git.
