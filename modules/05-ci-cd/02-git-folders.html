Databricks Git folders: clone, create and switch branches

A Git folder links a folder in your workspace to a Git repository. The notebooks inside are real files under version control, and you can branch, commit and sync them without leaving Databricks.

The idea

A repository inside the workspace

A Git folder is the Databricks name for a repository cloned into your workspace. It was formerly called a Databricks Repo. You clone it once, then work on its notebooks and files like any folder.

Three operations cover most daily work:

  • Clone: copy a remote repository into a Git folder. You provide the repository's URL and your Git provider credentials.
  • Create a branch: start a new line of work from an existing branch, usually main. In the Git dialog, you name the branch and choose its base.
  • Switch a branch: change which branch the folder's files show. The files change to match that branch.

Databricks recommends that each developer works on their own branch. Shared folders need care, because switching branch changes what the folder shows to everyone who uses it.

Everyday analogy

A shared bookshelf with a sheet of alternate editions. The shelf (the Git folder) holds the books you read. A branch is an alternate edition of the same book: same title, a different set of revisions. Switching editions swaps the pages on the shelf. If three readers share the shelf, swapping editions changes it for all three, so each reader should have an edition of their own.

How it works

One folder, one repository, many branches

The folder holds one repository's files. Each branch in it is a different set of files.

Setting up credentials

Cloning and pushing need your Git provider credentials, stored in the Databricks Git credentials settings. The provider decides what the token must allow. Keep tokens out of notebooks; they belong in the credentials settings, or in a secret.

Code

  
The same operations, as Git commands

  
The Git folder dialog runs commands like these for you:


git clone https://github.com/example/bakery-pipelines.git    # what "clone" does
git switch -c feature/shop-codes main                     # what "create branch from main" does
git switch main                                           # what "switch branch" does

  
You can also list Git folders from code with the Databricks CLI or the Repos API, which is the basis for CI/CD in lesson 05-04 onward. Check the current command names in the Databricks CLI reference.






  
What if I change this?

  
Branch operations and their effects

  

    
ChangeEffect

    
Create a branch from main instead of from another feature branchThe new branch has only main's commits. Use this as the default starting point.

    
Switch branch in a folder that others also useThe folder changes for everyone who uses it. Give each person their own Git folder.

    
Switch branch with uncommitted editsYour edits may be lost or blocked. Commit or discard first, and check what the UI reports.

    
Navigate away while the folder is in a detached HEAD stateChanges made there are not on any branch and can be lost. Create a branch before editing.

    
Add a new folder outside the sparse checkout patternThe commit and push fail with an error. Check the folder's sparse checkout settings.

ScenarioWhat happensFix

Don't confuse these

  
Git folder traps

  

    
Git folder vs repository
The Git folder is the workspace copy. The repository is the remote project it is linked to.

    
Repos vs Git folders
Repos is the former name. Git folders is the current name. Exam questions may use either.

    
Switching vs creating
Create makes a new branch. Switch changes which existing branch the folder shows.

    
Shared vs personal folder
A shared folder is one copy for everyone. A personal folder is yours, and switching it affects only you.
