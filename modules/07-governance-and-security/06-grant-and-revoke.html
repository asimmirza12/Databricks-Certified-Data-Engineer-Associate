GRANT and REVOKE in SQL and the UI

Giving and taking away access comes down to two SQL statements and one tab in Catalog Explorer. This lesson shows both, plus who is allowed to use them and how to check the result.

The idea

Give with GRANT, take with REVOKE

GRANT gives one or more privileges on a securable to a principal. REVOKE takes them away. The pattern is always the same:

  • GRANT <privileges> ON <object type> <name> TO <principal>
  • REVOKE <privileges> ON <object type> <name> FROM <principal>

The same can be done without SQL in Catalog Explorer: open the object, go to the Permissions tab, click Grant, pick the principal and the privileges, and confirm. Revoke from the same tab.

Who may grant or revoke on an object: its owner, the owner of the catalog or schema it sits in, anyone with MANAGE on it, or a metastore admin.

Check the result with SHOW GRANTS, which lists granted and inherited privileges, or the Permissions tab.

Two details: revoking a privilege that was never granted is not an error, and revoking on a table does not remove a privilege the principal inherits from the schema or catalog. To fully remove access, revoke it where it was granted.

Everyday analogy

The key register at the bakery. The manager writes "morning shift: front door key" in the register (GRANT) and crosses it out later (REVOKE). Only the manager or someone they trust with the register (owner or MANAGE) may write in it. Crossing out "back room key" does nothing if the shift still holds the master key for the whole building.

How it works

Two ways in, one set of grants

SQL and the UI are two front ends for the same permissions.

Try it

Build and run a GRANT or REVOKE

Choose who you are, then build a statement. Try granting as a plain user, revoking only at table level when the grant came from the schema, and revoking something that was never granted.

Statement

Grants that reach gold.daily

Code

GRANT, REVOKE and SHOW GRANTS

-- Several privileges in one statement
GRANT SELECT, MODIFY ON TABLE bakery.gold.daily TO `6f1c2b7e-0a4d-4c1e-9b8a-2d3e4f5a6b7c`;

-- Everything that applies to the object (not MANAGE)
GRANT ALL PRIVILEGES ON SCHEMA bakery.sandbox TO `bakery-engineers`;

-- Take it away
REVOKE MODIFY ON TABLE bakery.gold.daily FROM `6f1c2b7e-0a4d-4c1e-9b8a-2d3e4f5a6b7c`;

-- What is granted on the table, and to one principal
SHOW GRANTS ON TABLE bakery.gold.daily;
SHOW GRANTS `bakery-analysts` ON TABLE bakery.gold.daily;

-- Hand over ownership
ALTER TABLE bakery.gold.daily OWNER TO `data_admins`;

The service principal ID above is made up. In Catalog Explorer, the Permissions tab shows the same list and has Grant and Revoke buttons.

What if I change this?

Choices and their effects

ChangeEffect
Grant on the schema instead of the tableApplies to every table in it, now and later.
Revoke on the table when the grant was on the schemaNo effect on access: the schema grant still reaches the table.
Revoke something never grantedSucceeds quietly; nothing changes.
Grant as a user with only SELECTDenied: you need ownership, MANAGE, parent ownership or metastore admin.
REVOKE ALL PRIVILEGESRemoves the object's privileges, but not MANAGE.

Don't confuse these

Grant traps

TO vs FROM

GRANT ... TO; REVOKE ... FROM.

Revoke where granted

Inherited privileges are only removed at the level they were granted.

Who can grant

Owner, parent owner, MANAGE holder or metastore admin. Not someone with just SELECT.

Least privilege

Grant the narrowest privilege at the narrowest level that works.

Check yourself

Quiz

1. Which statement removes SELECT on a table from a group?

REVOKE ... FROM. DENY is not supported by Unity Catalog (next lesson).

2. Who can grant SELECT on bakery.gold.daily?

Holding a privilege does not let you pass it on.

3. Where in the UI do you grant access to a table?

The Permissions tab has Grant and Revoke buttons.

4. In the demo, you granted SELECT on the schema, then revoked SELECT on the table. Could the analysts still read gold.daily?

Revoke at the level where the privilege was granted.

Wrap up

Key takeaways

  • GRANT privileges ON object TO principal; REVOKE ... FROM principal.
  • Catalog Explorer's Permissions tab does the same thing.
  • Owners, parent owners, MANAGE holders and metastore admins can grant.
  • SHOW GRANTS shows granted and inherited privileges; revoke where the grant was made.
