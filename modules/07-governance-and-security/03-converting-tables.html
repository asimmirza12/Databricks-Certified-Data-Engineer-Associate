Converting between managed and external

Many teams start with external tables and later want the benefits of managed ones. Unity Catalog has a single command for that direction. Going the other way means making a copy.

The idea

One command one way, a copy the other way

External to managed: ALTER TABLE ... SET MANAGED. Databricks copies the data into managed storage, then switches the table over. The table keeps its name, history and grants, so queries and permissions keep working. Requirements from the docs:

  • The table must be Delta.
  • Run it on Databricks Runtime 17.3 LTS or above, or serverless compute.
  • You must own the table or hold MANAGE on it.
  • Writers pause briefly during the switch (about a minute for small tables, a few minutes for very large ones). Readers on recent runtimes see no downtime.
  • Stop scheduled OPTIMIZE jobs on the table while it converts.

Changed your mind? ALTER TABLE ... UNSET MANAGED points the table back to its old external location, within 14 days of converting. The old external files are kept for 14 days and then cleaned up.

Managed to external: there is no one-step command. You make a copy at a path with a deep clone (CREATE TABLE ... DEEP CLONE ... LOCATION) or a CTAS with LOCATION, point readers at the copy, then drop the old managed table.

Everyday analogy

Moving stock into the bakery's own storeroom. Moving flour from the rented unit into the storeroom is a service the shop offers: staff carry it over, update the inventory, and the door is only closed for a moment (SET MANAGED). For two weeks you can still ask to move it back. Moving flour out to a new rented unit means buying a second batch for there (a copy), then emptying the storeroom.

Code

Both directions

-- External to managed (Delta only; DBR 17.3 LTS+ or serverless; owner or MANAGE)
ALTER TABLE bakery.bronze.pos_sales SET MANAGED;

-- Check it worked: Type should now be MANAGED
DESCRIBE TABLE EXTENDED bakery.bronze.pos_sales;
SELECT table_type FROM system.information_schema.tables
WHERE table_catalog = 'bakery' AND table_schema = 'bronze' AND table_name = 'pos_sales';

-- Roll back within 14 days
ALTER TABLE bakery.bronze.pos_sales UNSET MANAGED;

-- Managed to external: copy to a path, then retire the managed table
CREATE TABLE bakery.share.daily_sales_export
  DEEP CLONE bakery.gold.daily_sales
  LOCATION 's3://bakery-share/daily_sales/';
DROP TABLE bakery.gold.daily_sales;   -- only after readers have moved

A CSV or JSON external table cannot be converted with SET MANAGED. Load it into a managed Delta table instead (CTAS or COPY INTO). Check the conversion page for current runtime versions and edge cases.

Don't confuse these

Conversion traps

Delta only

SET MANAGED needs a Delta table.

No SET EXTERNAL for this

Managed to external means copying.

Clone is a new table

A clone needs its own grants.

14 day rollback

UNSET MANAGED only works within 14 days.

Check yourself

Quiz

1. Which command turns an external Delta table into a managed table in place?

It copies the data into managed storage and switches the table over.

2. What do users notice after SET MANAGED?

Only a brief writer pause happens during the switch.

3. How do you get an external copy of a managed table?

UNSET MANAGED only undoes a recent SET MANAGED.

4. In the demo, what happened when you ran SET MANAGED on DBR 15.4 LTS?

Switch to serverless or a newer runtime.

Wrap up

Key takeaways

  • External to managed: ALTER TABLE ... SET MANAGED (Delta, DBR 17.3 LTS+ or serverless, owner or MANAGE).
  • It keeps the name, history and grants; writers pause briefly.
  • UNSET MANAGED rolls back within 14 days.
  • Managed to external: copy with DEEP CLONE or CTAS at a LOCATION.
