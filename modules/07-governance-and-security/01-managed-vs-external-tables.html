Managed vs external tables

Every Unity Catalog table has two parts: its description in the catalog, and its data files in cloud storage. Who looks after those files decides whether the table is managed or external. That choice changes what happens when you drop it.

The idea

Who owns the files?

A managed table lets Unity Catalog look after everything. You do not give a path. The data files go into the managed storage location set on the metastore, catalog or schema. Unity Catalog handles reads, writes, layout and clean-up. Managed tables are the default and the type Databricks recommends. Features such as predictive optimization only work on them.

An external table keeps its files at a path you choose, given with LOCATION. That path must sit inside a registered external location. Unity Catalog still governs who can query the table, but you look after the files. External tables make sense when other tools outside Databricks must read the files directly, or when the format is one managed tables do not support (such as CSV or JSON).

The big difference shows up on DROP TABLE:

  • Managed: the table disappears and its files are deleted, after a recovery period of 7 days by default. Within that period, UNDROP TABLE brings it back.
  • External: only the catalog entry is removed. The files stay in your storage until you delete them yourself.
Everyday analogy

Storing the bakery's flour. A managed table is the bakery's own storeroom: the shop decides where sacks go, cleans up, and throws out empty sacks (after keeping them a week in case of mistakes). An external table is flour kept in a rented unit across town: the shop's inventory lists it, but if you cross it off the list, the sacks are still sitting in the unit.

How it works

Same catalog entry, different file owner

Both tables are governed the same way. Only the file lifecycle differs.

Creating each kind

-- Managed: no path. Delta by default.
CREATE TABLE bakery.silver.sales (
  sale_id   BIGINT,
  store_id  INT,
  amount    DECIMAL(10,2)
);

-- External: you give the path. It must be inside an external location
-- on which you hold CREATE EXTERNAL TABLE.
CREATE TABLE bakery.bronze.pos_csv (
  sale_id BIGINT, store_id INT, amount DECIMAL(10,2)
)
USING CSV
OPTIONS (header 'true')
LOCATION 's3://bakery-pos/raw/';

-- Which kind is it? Look for Type: MANAGED or EXTERNAL
DESCRIBE TABLE EXTENDED bakery.silver.sales;

-- Dropped a managed table by mistake? List and restore within the recovery period
SHOW TABLES DROPPED IN bakery.silver;
UNDROP TABLE bakery.silver.sales;

To create either kind you need USE CATALOG, USE SCHEMA and CREATE TABLE. For an external table, add CREATE EXTERNAL TABLE, granted on the external location that covers its path. The recovery period can be changed per catalog or schema (Public Preview); check the docs for current limits.

What if I change this?

Choices and their effects

ChangeEffect
Leave out LOCATIONManaged table in the schema's managed storage.
Add LOCATIONExternal table at that path.
DROP a managed tableGone from the catalog; files kept for a 7 day recovery window by default, then removed (the clean-up can run later than day 7).
DROP an external tableGone from the catalog; files untouched.
UNDROP within the recovery periodTable, columns, properties and privileges come back. Primary and foreign key constraints must be re-added.
UNDROP after the recovery periodNot possible for a managed table; the files were purged.

Don't confuse these

Table type traps

Both are governed

External does not mean ungoverned. Unity Catalog checks permissions on both.

DROP is different

Managed files are purged later; external files stay forever.

LOCATION decides

Give a path and you get an external table.

UNDROP has a window

7 days by default. After that the managed files are gone.

Check yourself

Quiz

1. You drop an external table. What happens to its data files?

DROP on an external table only removes the catalog entry.

2. Which statement creates a managed table?

No path means Unity Catalog stores the files in managed storage.

3. A managed table was dropped 2 days ago with the default settings. What can you do?

It is still inside the default 7 day recovery period.

4. In the demo, what happened when you tried UNDROP 9 days after dropping a managed table?

After the recovery period, managed files are deleted for good.

Wrap up

Key takeaways

  • Managed: Unity Catalog stores and cleans up the files. Default and recommended.
  • External: you give a LOCATION inside an external location; you own the files.
  • DROP managed: files are kept for a recovery window, 7 days unless changed, then purged; UNDROP only works inside that window.
  • DROP external: only metadata is removed.
