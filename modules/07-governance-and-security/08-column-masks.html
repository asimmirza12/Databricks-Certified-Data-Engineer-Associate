Column masks

Sometimes everyone may query a table, but not everyone may see every value in it. A column mask rewrites one column's values on the fly, so the support team sees full email addresses and everyone else sees a hidden version, from the same table.

The idea

A function decides what each person sees

A column mask is a SQL user-defined function (UDF) attached to one column of a table. Every time anyone reads that column, Databricks calls the function with the real value, and the reader gets whatever the function returns. The table itself is not changed.

Inside the function you usually check who is asking with is_account_group_member('group'). If the reader is in an allowed group, return the real value; otherwise return a hidden version, such as '***', the last four digits, or NULL.

Rules to know:

  • The function's first parameter receives the column value, and it must return the same type (or one that can be cast to it). Extra inputs can come from other columns with USING COLUMNS.
  • One mask per column. A table can have masks on several columns.
  • Apply with ALTER TABLE ... ALTER COLUMN ... SET MASK; remove with DROP MASK.
  • To set or remove a mask you must own the table, or hold both MANAGE and SELECT on it, and have EXECUTE on the function.
  • The docs describe no automatic exemption, not even for the table owner, so build any exemptions into the function's logic (verify in the docs).
  • Readers need standard access mode compute (DBR 12.2 LTS+), a SQL warehouse, serverless, or dedicated compute on DBR 15.4 LTS+. Older runtimes fail safely and return no data.
Everyday analogy

The bakery's customer card file. Everyone can look up a customer, but the phone number is covered by a sticky note unless you work on the delivery desk. The note is not on the card itself; a clerk adds it as they hand the card over, depending on who is asking. That clerk is the mask function.

How it works

Same table, different values per reader

The stored value never changes; only what each reader receives.

Code

Create a mask function and attach it

-- 1. The function: same input and output type as the column
CREATE OR REPLACE FUNCTION bakery.gov.mask_email(email STRING)
RETURNS STRING
RETURN CASE
  WHEN is_account_group_member('support') THEN email
  ELSE concat(left(email, 1), '***@', split(email, '@')[1])
END;

-- 2. Attach it to the column
ALTER TABLE bakery.silver.customers ALTER COLUMN email SET MASK bakery.gov.mask_email;

-- A mask that also reads another column: show the full phone if the customer opted in
CREATE OR REPLACE FUNCTION bakery.gov.mask_phone(phone STRING, opted_in BOOLEAN)
RETURNS STRING
RETURN IF(opted_in OR is_account_group_member('support'), phone, concat('***', right(phone, 4)));

ALTER TABLE bakery.silver.customers
  ALTER COLUMN phone SET MASK bakery.gov.mask_phone USING COLUMNS (opted_in);

-- 3. Remove a mask
ALTER TABLE bakery.silver.customers ALTER COLUMN email DROP MASK;

Group names such as support are made up. The demo above uses a simpler phone rule (support and admins see the full number) than this code sample. Drop a mask from every table before dropping its function, or those tables become unreadable.

What if I change this?

Choices and their effects

ChangeEffect
Return NULL instead of a partial valueHides everything; joins and counts on the column change too.
Use USING COLUMNSThe decision can depend on other columns in the same row.
Forget to exempt the owner or adminsThey see masked values too.
Drop the function while a mask uses itQueries on the table fail.
Read from an old runtime or unsupported computeFails safely: no data returned.
Add a second mask to the same columnNot allowed; one mask per column.

Don't confuse these

Mask traps

Mask vs filter

A mask changes values in a column; a row filter removes whole rows.

Owners are masked

The docs describe no owner exemption; the function's logic decides (verify in the docs).

Same type

The function must return the column's type.

is_account_group_member

Checks account groups; recommended over is_member.

Wrap up

Key takeaways

  • A column mask is a SQL UDF that returns the value each reader is allowed to see.
  • SET MASK to attach, DROP MASK to remove; one per column; same return type.
  • is_account_group_member() inside the function decides who sees what; no automatic owner exemption is described.
