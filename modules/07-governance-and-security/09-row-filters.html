Row filters

The north region manager should see north sales, and the south manager south sales, from one shared table. A row filter quietly removes the rows a reader is not allowed to see, every time they query.

The idea

A yes-or-no function for every row

A row filter is a SQL UDF that returns a BOOLEAN, attached to a table. For each row, Databricks passes in the values of the columns you chose. If the function returns TRUE the reader sees the row; if it returns FALSE or NULL the row is left out, as if it were not there.

The function usually combines a column value with who is asking: "admins see everything; members of region_north see rows where region is North". When the rules are too many to write as code, keep them in a mapping table (which user or group may see which region) and look it up inside the function.

Rules to know:

  • One row filter per table. Apply with ALTER TABLE ... SET ROW FILTER fn ON (columns); remove with DROP ROW FILTER. You can also add it in CREATE TABLE ... WITH ROW FILTER.
  • Permissions are the same as for masks: owner of the table, or MANAGE and SELECT on it, plus EXECUTE on the function.
  • It applies to every reader, including the owner, unless the function says otherwise; the docs describe no owner exemption (verify in the docs).
  • Compute requirements match column masks; older runtimes fail safely and return no data.
  • Filters cannot be put on views, and time travel and clones are not supported on filtered tables.
Everyday analogy

The bakery's order book. Each branch manager asks for "the orders". The head office clerk hands over the book but quietly removes every page that belongs to another branch. Everyone thinks they got the whole book; each got only their part. The clerk's rule is the filter function.

Code

Two styles of row filter

-- Style 1: rules written in the function
CREATE OR REPLACE FUNCTION bakery.gov.region_filter(region STRING)
RETURNS BOOLEAN
RETURN is_account_group_member('data_admins')
    OR (region = 'North' AND is_account_group_member('region_north'))
    OR (region = 'South' AND is_account_group_member('region_south'));

ALTER TABLE bakery.gold.regional_sales SET ROW FILTER bakery.gov.region_filter ON (region);

-- Style 2: rules kept in a mapping table, so changes need no code
CREATE TABLE bakery.gov.region_access (user_email STRING, region STRING);
INSERT INTO bakery.gov.region_access VALUES
  ('ana@example.com', 'North'), ('ben@example.com', 'South');

CREATE OR REPLACE FUNCTION bakery.gov.region_filter_map(r STRING)
RETURNS BOOLEAN
RETURN is_account_group_member('data_admins')
    OR EXISTS (SELECT 1 FROM bakery.gov.region_access a
               WHERE a.user_email = session_user() AND a.region = r);

ALTER TABLE bakery.gold.regional_sales SET ROW FILTER bakery.gov.region_filter_map ON (region);

-- Remove the filter (do this before dropping the function)
ALTER TABLE bakery.gold.regional_sales DROP ROW FILTER;

Inside a filter, session_user() and is_account_group_member() check the person running the query. Turn ANSI mode on so type mismatches raise errors instead of silently becoming NULL (which would hide rows).

What if I change this?

Choices and their effects

ChangeEffect
Function returns NULL for a rowThe row is hidden, same as FALSE.
Mapping table instead of hard-coded rulesChange access with INSERT and DELETE; no function changes.
No admin exemption in the functionAdmins and the owner see filtered data too.
Try to add a second filter to the tableNot allowed; combine rules in one function.
Drop the function firstThe table becomes unreadable until the filter is dropped.
Query with time travelNot supported on a table with a row filter.

Don't confuse these

Filter traps

FALSE or NULL hides

Only TRUE shows the row.

One per table

Put all rules in one function.

Owners filtered too

The docs describe no built-in exemption; write it into the function.

Not on views

Filters attach to tables. (Views can contain their own WHERE logic.)

Check yourself

Quiz

1. What must a row filter function return?

TRUE keeps the row; FALSE or NULL hides it.

2. Which statement attaches a row filter?

A view can filter too, but it is a different object that people could bypass.

3. Why use a mapping table in a row filter?

Add or remove rows to change who sees what.

4. In the demo, with the group filter on, what did sam (owner, no group) see?

The owner is not in any allowed group, and the docs describe no owner exemption.

Wrap up

Key takeaways

  • A row filter is a BOOLEAN SQL UDF attached to a table; TRUE shows the row.
  • SET ROW FILTER fn ON (cols) to attach; DROP ROW FILTER to remove; one per table.
  • Use is_account_group_member() or a mapping table to decide; no automatic owner exemption is described.
