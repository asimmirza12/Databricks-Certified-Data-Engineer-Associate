ABAC: governed tags and policies

Masks and filters set one table at a time do not scale to hundreds of tables. Attribute-based access control flips it round: label the data with tags, write one policy that says what to do with anything carrying that label, and every matching table follows it.

The idea

Tag the data, write the rule once

Attribute-based access control (ABAC) decides access from attributes of the data, in practice its tags, instead of per-table settings.

Governed tags are tags defined once for the whole account, each with a list of allowed values, such as pii with values email, phone, address. Because the values are fixed, nobody can tag a column pii = emial by mistake. Tags on a catalog or schema flow down to its tables; column tags are set on each column.

Who can tag: managing governed tags has its own permissions (CREATE, MANAGE and ASSIGN on the tag). Labelling a table or column with a governed tag takes two permissions at once: ASSIGN, which you hold on the tag itself, and APPLY TAG, which you hold on the table or column.

Policies are attached to a catalog, schema or table and apply to every matching table below. A policy says:

  • which function to apply: a ROW FILTER or a COLUMN MASK (the same kind of SQL UDF as in the last two lessons);
  • to whom: TO principals, with EXCEPT for exemptions;
  • to what: tables matching a WHEN condition and columns matching MATCH COLUMNS, using has_tag('key') or has_tag_value('key', 'value').

To create a policy you need MANAGE on (or ownership of) the object you attach it to, plus EXECUTE on the function.

Everyday analogy

Allergen stickers at the bakery. Instead of writing a separate warning for every cake, staff put an official "contains nuts" sticker on any cake with nuts (governed tag; only approved sticker types exist). One shop rule says "anything with a nuts sticker goes behind the counter" (policy). A new cake with the sticker follows the rule the moment it is labelled.

How it works

One policy, many tables

The policy finds columns by tag, not by name, so email, cust_email and contact are all covered.

Try it

What the reader sees

Code

Tag columns and create a policy

-- Tag the columns (the governed tag pii and its allowed values exist already)
ALTER TABLE bakery.silver.customers ALTER COLUMN email      SET TAGS ('pii' = 'email');
ALTER TABLE bakery.silver.orders    ALTER COLUMN cust_email SET TAGS ('pii' = 'email');

-- The mask function (no group checks needed: the policy decides who)
CREATE OR REPLACE FUNCTION bakery.gov.hide_email(email STRING)
RETURNS STRING
RETURN concat(left(email, 1), '***@', split(email, '@')[1]);

-- One policy for the whole schema
CREATE POLICY mask_emails
ON SCHEMA bakery.silver
COMMENT 'Hide emails from everyone except data admins'
COLUMN MASK bakery.gov.hide_email
TO `account users` EXCEPT `data_admins`
FOR TABLES
MATCH COLUMNS has_tag_value('pii', 'email') AS e
ON COLUMN e;

-- See which policies apply
SHOW POLICIES ON SCHEMA bakery.silver;

Policies can also be created in Catalog Explorer (Policies tab). ABAC needs serverless compute, a SQL warehouse, or DBR 16.4+ with a supported access mode; older runtimes fail closed. Some ABAC parts (metastore-level policies, DENY policies, identity attributes) were in Beta when checked. Verify current status and syntax in the docs.

What if I change this?

Choices and their effects

ChangeEffect
Tag a new column pii = emailIt is masked immediately; no ALTER on the table's mask.
Remove the tagThe policy no longer matches that column; values show.
Attach the policy to the catalog insteadEvery schema in the catalog is covered.
Add a group to EXCEPTThat group sees real values.
Use a value not in the governed tag's listRejected: governed tags only accept their allowed values.
Delete the mask function or the governed tagQueries on matching tables fail (fail closed).

Don't confuse these

ABAC traps

Columns do not inherit

Table and schema tags flow down to tables; columns need their own tags.

Two permissions to tag

You need the tag's ASSIGN permission and the object's APPLY TAG privilege together.

TO and EXCEPT

Who is affected lives in the policy, not in group checks inside the function.

Fail closed

Missing tags or functions make queries fail rather than leak data.

Check yourself

Quiz

1. What makes a tag "governed"?

Allowed values stop typos and keep tags consistent.

2. Where can an ABAC policy be attached so it covers many tables?

It can also be attached to one table.

3. In a policy, how do you exempt the data admins?

Principals in EXCEPT are not affected by the policy.

4. In the demo, after creating the policy, what happened to the new feedback table?

The schema policy matches any column tagged pii = email.

Wrap up

Key takeaways

  • ABAC applies filters and masks by tag, from policies on a catalog, schema or table.
  • Governed tags have fixed allowed values; tagging takes the tag's ASSIGN permission plus APPLY TAG on what you label.
  • Policies name the function, TO and EXCEPT principals, and WHEN / MATCH COLUMNS conditions with has_tag and has_tag_value.
  • New tagged tables are covered automatically; missing tags or functions fail closed.
