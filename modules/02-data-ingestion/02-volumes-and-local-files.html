Uploading local files and Unity Catalog volumes

The idea

Two doors for a local file

A "local file" is one that sits on your own laptop, such as a spreadsheet export someone emailed you. There are two ways to get it into Databricks.

  • Straight into a table. The "Create or modify a table" page in the UI takes the file, shows a preview, lets you fix column names and types, and creates a managed Delta table. Nothing else to do.
  • Into a volume first. You upload the file to a volume, where it stays as a file. Then a query or pipeline reads it into a table.

The first door is quickest for a one-off. The second is what real pipelines use, because the raw file is kept, and the same loading code can run again when the next file arrives.

A volume is a Unity Catalog object that holds files of any kind. It lives in a schema, next to tables, and gets the same three-part name. Because it is a Unity Catalog object, access to its files is controlled by grants, exactly like access to a table.

Everyday analogy

A post room in an office. A parcel arrives at the front desk. You can open it and put the contents straight onto the shelves: quick, but the box is thrown away. Or you can log it into the post room first, where it is labelled, kept and only handled by people with a key, and then unpack it by a set routine. The post room is the volume.

How it works

From laptop to table

With door 2 the file remains in the volume after the table is loaded, so you can load it again or check what was really sent.

Volume paths

Every file in a volume has one fixed style of path, built from the volume's three-part name:

/Volumes/<catalog>/<schema>/<volume>/<folders>/<file>

The same path works in SQL, in Python, in the file browser and on every cloud. You never need the raw s3:// or abfss:// address.

Two kinds of volume

Managed volume

Unity Catalog chooses where the files are stored and looks after them. Dropping the volume removes the files. The easy default.

External volume

Points at a folder in cloud storage that already exists, registered through an external location. Dropping the volume leaves the files. Use it when another system also writes to that folder.

Code

Working with a volume

-- Create a managed volume inside a schema.
CREATE VOLUME IF NOT EXISTS bakery.landing.till_files
  COMMENT 'Raw files from the shop tills';

-- An external volume points at an existing cloud folder instead.
CREATE EXTERNAL VOLUME bakery.landing.supplier_drop
  LOCATION 's3://bakery-supplier-drop/incoming/';

-- Who may read and who may add files.
GRANT READ VOLUME  ON VOLUME bakery.landing.till_files TO `analysts`;
GRANT WRITE VOLUME ON VOLUME bakery.landing.till_files TO `data_engineers`;

-- See what is in it.
LIST '/Volumes/bakery/landing/till_files/';

Once a file is in the volume, read_files lets you query it like a table, and one more line turns it into a real table.

-- Look at the file without loading it anywhere.
SELECT * FROM read_files(
  '/Volumes/bakery/landing/till_files/orders.csv',
  format => 'csv',
  header => true
) LIMIT 10;

-- Load it into a bronze table, keeping a note of which file each row came from.
CREATE TABLE bakery.bronze.orders_raw AS
SELECT *, _metadata.file_path AS source_file
FROM read_files('/Volumes/bakery/landing/till_files/', format => 'csv', header => true);
# The same in Python. Volume paths work like ordinary file paths.
orders = (spark.read.format("csv")
    .option("header", "true")
    .load("/Volumes/bakery/landing/till_files/orders.csv"))

# Copy a file from one place in a volume to another.
dbutils.fs.cp("/Volumes/bakery/landing/till_files/orders.csv",
              "/Volumes/bakery/landing/till_files/archive/orders.csv")

read_files guesses column types by default. Auto Loader, which you meet in lesson 02-05, does the opposite and reads CSV and JSON columns as text unless told otherwise. That difference is a classic exam trap.

What if I change this?

Small changes, different outcomes

ChangeEffect
Use the upload page instead of a volumeYou get a managed Delta table at once. The original file is not kept anywhere you can reach.
Point read_files at a folder instead of one fileEvery file in the folder is read as one dataset.
Leave out _metadata.file_pathThe table loads fine, but you can no longer tell which file a bad row came from.
Grant READ VOLUME but not WRITE VOLUMEThe person can list and read files, but cannot upload, change or delete them.
Drop a managed volumeIts files are removed. Drop an external volume and the files stay in your cloud folder.
Try to upload a file larger than the UI allowsThe UI refuses. Larger files go in with the command line tool, the SDK or the Files API.

Ways to get a file into a volume

The UI

Open the volume in the catalog browser and upload. Simple, with a size limit per file.

Command line

The Databricks CLI copies files from your machine, for example databricks fs cp. Scriptable.

Code

The Databricks SDK or the Files API, for programs that deliver files automatically and for very large files.

Don't confuse these

Volume traps

Volume vs table

A volume holds files. A file in a volume is not a table and cannot be registered as one. You load it into a table.

Managed vs external volume

Same idea as tables. Managed: Unity Catalog owns the files. External: you do, and they survive a drop.

READ VOLUME vs SELECT

SELECT is the privilege for tables. Files in volumes use READ VOLUME and WRITE VOLUME.

read_files vs Auto Loader defaults

read_files infers column types by default. Auto Loader reads CSV and JSON columns as strings by default.

Check yourself

Quiz

1. What is the path of file orders.csv in volume till_files, schema landing, catalog bakery?

Volume paths always start with /Volumes/, followed by catalog, schema and volume.

2. Which privilege lets someone upload a file to a volume?

WRITE VOLUME covers adding, changing and deleting files. READ VOLUME is for listing and reading only.

3. A monthly file must be loaded the same way every time, and the original kept. Which approach fits?

The volume keeps the raw file, and the loading step is code that can be rerun each month.

4. You drop an external volume. What happens to its files?

External means Unity Catalog only points at the folder. Dropping the volume removes the pointer.

Wrap up

Key takeaways

  • A local file can go straight to a table from the upload page, or into a volume first.
  • A volume is a Unity Catalog object for files, with paths starting /Volumes/.
  • Access to files uses READ VOLUME and WRITE VOLUME.
  • read_files queries files directly and turns them into tables.
  • Use a volume whenever the load will be repeated or the raw file must be kept.
