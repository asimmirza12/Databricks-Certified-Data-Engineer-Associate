Lakeflow Connect: standard vs managed connectors

Lakeflow Connect is the family name for Databricks ingestion tools. It has two branches. One does everything for you. The other gives you the parts and lets you build.

The idea

Ready-made, or build it yourself

A connector is a piece of software that knows how to read from one kind of source. Lakeflow Connect groups all of Databricks' connectors into two kinds.

  • A managed connector is a complete, ready-made pipeline for one specific source, such as Salesforce or SQL Server. You say what to connect to and which tables you want. Databricks handles logging in, finding changes, retrying after failures and adapting when the source's columns change. You cannot alter how it ingests.
  • A standard connector is a building block. It knows how to read a kind of source, such as files in cloud storage or a message stream, but you write the pipeline around it: what to read, how often, what to do with it. More work, more control.

Both kinds land data in tables governed by Unity Catalog. That is the phrase the exam guide repeats: "Unity Catalog-governed tables".

Everyday analogy

Getting a bookshelf. A managed connector is a shelf that arrives assembled and is fitted for you. It suits the alcove it was made for and you cannot change its design. A standard connector is a box of good timber, brackets and screws. You can build exactly the shelf you need, any size, any shape, but you do the building and you fix it when it wobbles.

How it works

What sits between the source and your table

On the managed side the shaded boxes are provided for you. On the standard side the plain boxes are yours to write and maintain.

What you meet in each branch

Managed: SaaS applications

Business software run by another company, such as a sales or HR system. The connector logs in with a saved connection and copies the objects you pick, incrementally.

Managed: databases

Operational databases such as SQL Server. The connector reads the database's change log (CDC) so inserts, updates and deletes all arrive. It has an extra part called a gateway: lesson 02-08.

Standard: files in cloud storage

Files landing in S3, ADLS or GCS, or in a volume. Read with Auto Loader, COPY INTO or read_files. Lessons 02-04 to 02-07.

Standard: message streams

Systems that carry a constant flow of small messages, such as Apache Kafka. Read with Structured Streaming or in a pipeline.

The list of sources with a managed connector grows from release to release. Do not memorise a list. Learn the two kinds and check the docs for whether a given source has one.

Code

How much you write in each branch

A standard connector is used in code that you write. This is a complete, working ingestion of JSON files:

-- STANDARD: you write the statement, choose the options and schedule it.
CREATE OR REFRESH STREAMING TABLE bakery.bronze.web_orders_raw
SCHEDULE EVERY 1 HOUR
AS SELECT *, _metadata.file_path AS source_file
FROM STREAM read_files(
  '/Volumes/bakery/landing/web_orders/',
  format => 'json'
);

A streaming table is a table that loads only new data each time it refreshes. You will see it often from here on.

A managed connector is mostly configured in a form. Behind the form is a short description like this one, which you might keep in a file (Module 05):

# MANAGED: you describe WHAT to ingest. There is no reading or writing logic to write.
# Illustrative shape only. Check the connector's documentation for exact field names.
ingestion_definition:
  connection_name: bakery_crm_connection     # saved login details
  objects:
    - table:
        source_table: Customer                # what to copy from the source
        destination_catalog: bakery
        destination_schema: bronze            # where it lands

Managed or standard for the same job

ChangeEffect
Use a managed connector instead of writing your own readerFar less to build and maintain. You accept its behaviour as it is: you cannot add your own steps inside it.
Use a standard connector for a source that also has a managed oneFull control over every step. You now own authentication, change tracking, retries and schema changes.

Don't confuse these

Connector traps

Managed connector vs managed table

"Managed" means "Databricks looks after it" in both, but they are unrelated. One is an ingestion pipeline, the other a kind of table.

Standard does not mean basic

Standard connectors are the more flexible kind. Auto Loader, a standard connector, handles millions of files.

Connection vs connector

A connector is the software that reads a source. A connection is a saved Unity Catalog object with the address and login for one particular source system.

Lakeflow's three parts

Lakeflow Connect ingests. Lakeflow Spark Declarative Pipelines (formerly Delta Live Tables) transforms. Lakeflow Jobs orchestrates. Questions often hinge on which is which.

Check yourself

Quiz

1. What is the main difference between managed and standard connectors?

The trade is effort against control. Both write to Unity Catalog tables.

2. Auto Loader reading files from cloud storage is which kind?

File ingestion with Auto Loader, COPY INTO or read_files is the standard branch: you write and configure it.

3. A team must transform each record with their own code at the moment it is ingested. What should they use?

Managed connectors do not let you add steps. Standard connectors are used inside code you control.

4. In the demo, what did you have to set up yourself for the SQL Server source using a managed connector?

You describe what to ingest. Reading changes, applying them and retrying are the connector's job.

Wrap up

Key takeaways

  • Lakeflow Connect has two kinds of connector: managed and standard.
  • Managed: a ready-made pipeline for a specific application or database. Least effort, no customising.
  • Standard: building blocks such as Auto Loader that you configure. Most control.
  • Both land data in Unity Catalog-governed tables.
  • A connection stores the login details that a managed connector uses.
